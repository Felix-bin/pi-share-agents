# S4：双模式对照实验框架设计

- 日期：2026-09-20
- 状态：设计草案，待评审
- 依赖：[S3 eBPF I/O 观测](2026-09-19-synapse-ebpf-io-metering-design.md)（度量来源）
- 相关：`src/synapse/metering.ts`、`reference/synapse-py/源代码及readme文档/src/synapse/eval/`

## 1. 背景

赛题的评分中"实验验证"占 15 分、"通信效率"占 25 分，且明确要求：

> 系统需同时支持"纯文本协作模式"和"结构化协议协作模式"，并在相同任务条件下完成可复现实验对比；
> 系统需至少设计 2 组具有关联性的连续任务……
> 系统需统计并展示 Agent 间消息次数、文本通信 token 或字符开销、非文本状态传递次数及数据规模、
> 单任务总耗时、共享记忆命中率及整体性能提升情况；
> ……并能稳定执行不少于 10 轮连续任务。

本仓库已有计量层（`metering.ts`：追加写事件日志 + 纯函数聚合，日志是主记录、聚合可离线重算），
以及 S3 的内核侧账。**缺的是把它们组织成实验的那一层**：跑什么任务、怎么保证同条件、
怎么聚合成可比较的结论。

Python 原型有 `eval/` 与 `qa/`（实验框架与问答流水线），是本设计的**对照物**——
判断某个做法是否已被验证过，先看它。但原型是独立 Python 包，本仓库是 Pi 扩展，
只有机制对应，没有代码对应。

## 2. 范围

### 2.1 做

- 一个实验运行器：在**同任务、同模型、同配置、同随机种子**下，顺序隔离地跑 text 与 structured 两档。
- 至少 2 组**具有关联性**的连续任务，用于验证记忆复用。
- 一个聚合器：从计量日志与 S3 的内核账产出赛题要求的全部指标。
- 一份**可溯源的产物**：每个主张都能追到 run 目录与原始日志。

### 2.2 不做

- 不接入需要付费 API 的大规模数据集作为默认。默认必须能离线自检。
- 不做统计推断的完整装备（配对检验、置信区间可以有，但不是第一版的门槛）。
- 不改 SYNAPSE 的协议、传输或记忆实现。S4 只**消费**它们。
- 不做可视化。先把数字和溯源做对。

## 3. 架构

```text
       实验定义（任务集、模式、种子、轮数）
                      │
                      ▼
              ┌───────────────┐
              │  实验运行器    │  顺序隔离：一档跑完再跑下一档
              └───────┬───────┘
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
   text 模式                  synapse 模式
        │                           │
        └─────────────┬─────────────┘
                      ▼
      <storageRoot>/metering/<runId>.jsonl   （已有）
      <storageRoot>/trace/<runId>.ndjson     （S3，可选）
                      │
                      ▼
              ┌───────────────┐
              │   聚合器       │  纯函数：日志 → 指标
              └───────┬───────┘
                      ▼
            实验报告 + 主张-证据对账表
```

### 3.1 顺序隔离，不并行

两档必须**顺序**跑，不能并行。并行会让两档争抢同一台机器的 CPU、页缓存与网络，
时延数据因此不可比；而时延正是赛题要的指标之一。

代价是实验耗时翻倍。这是必须付的。

### 3.2 聚合器是纯函数

与 S3 的 joiner 同一设计：输入是日志数组，输出是指标对象。
不碰文件系统、不需要真机，因此**每一种聚合逻辑都能在 CI 里被证明**。

这一点在 S3 上已经验证有效——S3 唯一做判断的模块被完整覆盖，
而那正是唯一可能算错的地方。S4 的聚合器同理。

## 4. 关键决策

### 4.1 "同条件"必须是可证明的，不是声称的

A/B 实验的全部可信度系于"两档条件相同"。因此实验产物必须记录并断言：

- 模型标识与版本
- 随机种子
- 配置快照（`SynapseConfig` 的完整序列化）
- 语料/任务集的内容指纹
- 两档之间**没有**共享记忆残留（除非该实验就是要测跨任务复用）

最后一条最容易出错：记忆是跨任务累积的，若 text 档先跑并写入了记忆，
synapse 档就站在了它的肩膀上，对比因此作废。**每档必须从声明的记忆状态开始**，
并在产物中记录起始状态的指纹。

### 4.2 记忆复用要分两种实验，不能混

赛题同时要"记忆复用效果"和"通信效率"。这两件事需要相反的实验设置：

- **通信效率对照**：两档都从**空记忆**开始，比较同一任务的开销。
- **记忆复用验证**：同一档内跑关联任务序列，比较**后续任务**相对首个任务的开销下降。

把两者混在一次运行里会得到无法解释的数字。实验定义必须显式声明属于哪一种。

### 4.3 指标口径必须写死，且与 S3 分栏

赛题要的指标里有几个口径必须一次定清楚：

| 指标 | 口径 |
|---|---|
| 消息次数 | 一次通过委派接缝 = 一次投递；重试是新的 attempt 而非重复投递（沿用 `metering.ts` 现有语义） |
| 文本开销 | `text.handoffBytes` 与模型 token 分别报告，**不混为一谈** |
| 非文本传递规模 | `state.sentBytes`，与传输层字节分栏 |
| 单任务耗时 | `duration.byTask`，墙钟跨度，嵌套子任务不重复计入 |
| 记忆命中率 | `memory.hitRate`，`"N/A"` 当查询数为零 |
| 内核侧字节 | 来自 S3，**与应用层自报字节分栏展示，绝不相加** |

最后一条沿用 S3 §5.1 的判断：两者测的是不同的东西。

### 4.4 证据不全时不出数字

沿用贯穿本系列的纪律：`unavailable` 是"没报上来"，`"N/A"` 是"这个部署产不出来"，
两者都不得被静默替换为 `0`。

对 S4 而言这意味着：**一次模型用量缺失的运行，不得产出 token 节省率。**
`aggregateMetering` 已经把这条编码进 `model.complete`——只有当父子两侧用量都完整报告时
才计算总成本。S4 必须尊重它，而不是绕过去取个近似值。

## 5. 失败行为

| 情况 | 处理 |
|---|---|
| 某一档中途失败 | 整个对照作废，不得只报成功的那一档 |
| 模型用量缺报 | 该指标记 `unavailable`，其余指标照常报告 |
| S3 内核账不可用 | 内核侧指标记 `"N/A"`，应用层指标不受影响 |
| 记忆起始状态与声明不符 | 拒绝运行——这是对照的根基 |
| 轮数不足 10 | 如实报告实际轮数，不得四舍五入到赛题要求 |

## 6. 测试与验收

**CI 层**：聚合器的全部逻辑——指标计算、缺证据判定、两档差值、跨任务下降曲线。
用构造的日志数组测，不需要模型、不需要网络、不需要密钥。

**离线自检**：一组可随仓复现的小规模任务，不调用任何付费 API（用确定性 stub），
证明运行器能完整走通两档并产出报告。这是 CI 可跑的最大范围。

**真实实验（手动，出报告）**：

1. **可复现** —— 同配置同种子跑两次，字节类指标完全一致，时延可波动。
2. **对照有效** —— 两档确实在同条件下运行，产物中的条件指纹一致。
3. **≥10 轮连续任务**稳定执行。
4. **主张可对账** —— 报告里每个数字都能追到 run 目录与原始日志行。

第 4 点是设计目标而非装饰：Python 原型用 `docs/claim-evidence.csv` 做三跳对账
（主张 → 文件 → run/测试），S4 应当有等价物。**一个无法对账的数字在评审面前等于没有。**

## 7. 开放风险

- **任务集未定。** Python 原型用 HotpotQA / MuSiQue / CoQA。沿用它们可与原型结果互相印证，
  但需确认数据获取与许可；本仓库的默认必须是离线可跑的小样本。
- **模型调用成本。** 真实 A/B 需要成对调用，样本量与预算直接冲突。
  原型的做法是点估计加明确标注 N 值（如"N=3 探索性"）——诚实标注优于虚张的大 N。
- **上游 Python 原型无 LICENSE。** 可以阅读参考思路，**代码不得搬入本仓库**（MIT）
  而未先取得授权。见 `docs/synapse-python-prototype.md`。
- **S3 的内核账目前没有生产调用方。** S4 会是第一个真实消费者之一，
  须遵守其 `{kind: "not-collected"}` 与空 `TraceLog` 不可互换的契约。

## 8. 交付边界

S4 交付后，仓库能在同条件下产出一份可复现、可溯源、在证据不全时诚实说 `unavailable` 的对照报告。

它不改进任何机制，只让已有机制的收益**可被证明**——而这正是赛题 15 分"实验验证"
与 25 分"通信效率"所要求的东西。
