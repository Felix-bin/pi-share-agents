## 1. EXP-A 主对比（M3 + 通信效率 25 分，决赛核心数字）

**问题**：结构化协作（SYN，含 SHM 状态平面）相对纯文本协作（TXT）在同任务下省多少 token、多少交接字节、多少耗时；主流框架（CrewAI/AutoGen）作参照系。

**设计**（继承学长装置 + E1 口径，SHM 并入后重跑）：
- 臂（4 个，无消融臂——消融独立为 EXP-AB）：
  - **TXT**：纯文本协作模式（SYNAPSE 的 text 模式，同 harness 同角色）
  - **SYN**：完整结构化形态（信封协议+状态平面+共享记忆+autoDistill，**SHM 常开**）
  - **CrewAI / AutoGen**：主流框架参照臂
- 任务族：**R 组（SWE-QA Flask 仓库级关联问答）+ Q 组（MuSiQue 多跳）**——同题配对、臂交替、n=10/臂（R）+ n=6（Q）
- 模型：bailian deepseek-v4.1-flash（judge 用 deepseek-v3.2，同族偏差如实披露）
- 冻结判定：TXT−SYN token 配对差 CI 下界 > 0（"显著节省"）；交接字节/耗时并列报；质量非劣（judge 五维，δ=5）；框架臂只作参照系报告（不设击败判据）
- **SHM 的落点**：SYN 臂的常态（不是变量）；state 传递次数与规模进 M8 账

**框架臂公平性（已核查学长装置，结论：公平，沿用）**：
1. 同模型、同任务、同角色提示词（机械剪除 pi 专属段并留痕）、同工具集（pi 工具经 tool-server 以框架原生工具形式提供）；
2. 编排=**框架自己的推荐/默认协作**：CrewAI `Process.sequential`+框架默认上下文聚合（1.15.22 顺序任务自动携带全部上游输出，事件总线记录实际传入内容）；AutoGen `RoundRobinGroupChat`+默认广播+`reflect_on_tool_use`（并修掉默认 `max_tool_iterations=1` 的残废值）；
3. 全程可审计：handoffs.jsonl 逐 agent 记录实际收到的消息，token 从记录代理的 provider usage 取（不采信框架自报）。
历史教训已吸收：弱模型（qwen-flash）下框架质量崩塌是模型问题不是装置问题——正式跑统一 deepseek-v4.1-flash。

**已有可复用**：09-26/27 初步数字（R 组 TXT−SYN −33.9% 不跨 0 等）方向性成立；本实验=SHM 并入后的**正式版**（数字以新版为准，旧版只作方向引用）。

## 1b. EXP-AB 核心机制消融（M4/M5/M7 的机制归因 + 实验验证 15 分）

**问题**：SYNAPSE 的核心机制各自贡献多少？——回答"结构化的收益从哪来"，也是答辩"机制归因"问的防弹衣。

**设计**（独立于主对比；**唯一允许关 SHM 的实验**）：
- 消融因子（3 个，对齐赛题三问；每次只关一个机制，其余保持完整形态含 SHM）：
  - **SYN−state**：非文本状态传递关闭（状态平面降级为文本交接）→ 归因 M4
  - **SYN−memory**：跨任务共享记忆清空（每任务冷启动，协议/状态/SHM 照常）→ 归因 M5/M7
  - **SYN−shm**：共享内存段关闭（存储回文件路径，协议/状态/记忆照常）→ 归因 OS 层贡献
- 配置：SYN-full（=EXP-A 的 SYN 臂，不重跑、直接引用）+ 3 个消融配置；R 组前 6 题 × 3 配置
- 判定（冻结）：各消融配置对 SYN-full 的 token 配对差与质量非劣；**SYN−shm 的预期=token 与质量均不劣**（SHM 收益在宿主侧与激活稳定性，token 账预期不变——如实报告，这正是"SHM 不省 token 但值得做"的诚实证据）；SYN−state 与 SYN−memory 的方向预期从历史（E1/§10.9、R 组 +8.0%）继承但不预设立场
- 边界：不做的消融不虚构（autoDistill/结果块句柄化等机制不在本轮，避免组合爆炸；列为决赛后扩展）

## 2. EXP-B 关联任务链（M7 + 记忆复用 20 分）

**问题**：≥2 组关联性连续任务上，共享记忆复用是否减少重复计算/降低开销/提升质量；跨任务复用命中率与效率（M8 原文要求"共享记忆命中率"）。

**设计**（学长 M 组"重访链"装置直接扩展 + LongMemEval 专项）：
- 链 1（R-链，同仓库关联）：Flask 仓 5 题连续（同 storageRoot 跨任务保留记忆）vs 同 5 题独立冷启动——**这就是学长 M 组设计**（前 5 题+原样重访 5 题，判定规则已冻结于数据产生前）
- 链 2（Q-链，跨任务主题关联）：MuSiQue 同主题 4 连问
- 链 3（**L-链，LongMemEval 检索准确性专项**，2026-10-01 用户裁决新增）：官方长期记忆问答基准（arXiv 2410.10813）——每个实例的对话历史灌入 SYNAPSE 共享记忆库，问题做语义检索，官方口径**会话级召回率@5**。规模=标准版（含干扰会话）抽 100 例；装置 09-26 已通（oracle 版自检 100%），扩样只花嵌入成本。**定位：评分原文"跨任务记忆复用的准确性"的权威基准证据**——链 1/2 测"效率"半边（token/耗时），链 3 测"准确性"半边，三者合覆盖 20 分评分原文
- 指标（M8 口径）：**记忆命中率**（memory-reuse/memory-query，账本字段现成）、token 配对差、重访题质量、单任务耗时；链 3 另加官方召回率
- 冻结判定：链上 vs 冷启动 token 配对差 CI；命中率并列报；"减少重复计算"用重访题的检索次数下降佐证；链 3 报召回率点估计+区间（n=100 二项区间），与官方基线方法一致
- **SHM 的落点**：跨任务保留记忆时**段也跨任务驻留**（同 storageRoot）；链 3 的灌库/检索全程 SHM 常开（SYNAPSE 完整形态跑）
- **排除声明（用户裁决）**：SWE-bench **不进**本届实验——patch 级判定需逐题环境重建，装置与判定成本在决赛窗口内不可控；仓库级代码问答维度由 SWE-QA（ACL 2026，官方判分）承担

**benchmark 说服力总述（报告写作时照此口径）**：三个基准各对准一个评分维度——SWE-QA（ACL 2026，官方 judge 盲评）对准协作场景与 M7 关联任务、MuSiQue（NeurIPS 2021，规则 EM/F1）对准知识分析场景、LongMemEval（arXiv 2410.10813，官方召回口径）对准记忆复用准确性；全部公开基准+外部判分，无自编题。"单题为何需要多 Agent"的预期质疑在报告中主动回答：我们测的是协作机制的开销与复用，任务经四角色拆解后通信才存在。

## 3. EXP-C 状态传递账与四环说明（M4 + 状态传递创新 20 分）

**产出两件**：
1. **M8 口径的聚合脚本**（新写，一次性）：从 v7 账本+sweqa analyze 输出统一表——Agent 间消息次数、token/字符开销、**非文本状态传递次数及数据规模**（state-prepare/send/receive/consume 事件×字节）、单任务耗时、记忆命中率、整体提升。每个 EXP-A/B run 都能一键出这张表。**这张表就是实验报告的骨架**。
2. **四环说明文档**（写进设计文档/答辩）：状态向量怎么生成（embed）、怎么传（信封+**共享内存段驻留**）、怎么收（信封校验+段 attach）、怎么用（stateSearch 排序）——SHM 让"传递方式"一环有了 OS 层答案（M10 鼓励的共享内存）。

**SHM 证据链（附录级，不占主叙事）**：真机段协议单测 21/21、E0b 十轮零文件读、E0c 任务内激活（corpus-load=0）——作为"非 demo"的工程可信度证据。
