## 2. 判据与基线

对每个 (grid, threshold) 组合、每对 (Y, B)：

1. `yq = quantize(Y, grid)`、`bq = quantize(B, grid)`；
2. `payload, nnz = encodeDelta(yq, bq, {grid, threshold})`；
3. `Ŷ = dequantize(decodeDelta(payload, bq), grid)`；
4. 用 `rankCorpusChunks`（**生产排序**：`state-retrieval.ts` 中被 `retrieveWithState` 逐字调用的同一个函数）
   分别算 `topk(Y)` 与 `topk(Ŷ)`，k=5；
5. 一致性 = 两个 chunkId 列表**有序且逐位相等**。

同时报告三个诊断量：

- **top-1 一致**：只比第 1 名 —— 下游真正决定子代理答案的那一项；
- **top-5 集合一致**：同名集合、允许换序 —— 区分"换序"与"换结果"；
- **量化上界（quantizeOnly）**：同一 grid 下**完全不做残差**（直接把 `yq` 反量化去检索）的有序一致性。
  该列**不读 threshold**，只取决于 grid；某行上界低说明是 **grid 太粗**，而不是 threshold 太严。

每行还带一个按 pair 打包的 `outcomes` 位集（每位一对，base64），因此"两个组合到底差在哪几对"可由
随卡 JSON 直接复算，不必信作者的汇总数字。

## 4. 关键发现：为什么没有 100%

**没有任何组合达到 100% 有序一致性**（`perfectCombinations = 0`）。这不是实现缺陷，而是两个可测量的量
处在同一量级的结果。

### 4.1 残差扰动与排名边界同量级

| 量 | followup | progression |
|---|---|---|
| 参考排序"第 5 名 − 第 6 名"余弦差 中位数 | 5.499e-3 | 4.663e-3 |
| 同 p10 | 8.997e-4 | 7.507e-4 |
| 同 均值 | 8.736e-3 | 8.188e-3 |

threshold = 0.99 的残差把查询向量扰动 `‖Ŷ − Y‖ = sqrt(2(1 − cos)) = 0.1414`（单位向量）。

**关键是这个扰动如何作用到每一条 chunk 的余弦上，而不是它的范数本身。** 一个方向随机、范数为 ε 的扰动，
在 d = 1024 维里对某条固定余弦的改变量标准差约 `ε/√d = 0.1414/32 ≈ 4.4e-3` —— 与中位排名间隙
5.5e-3 **同一量级**（比值 0.80）。因此名次重排是**统计上必然**的：观测到的约 43% 翻车率与这个量级一致。

必须同时说明两点，否则这个比较会被读成诡辩：

- 普通 Cauchy–Schwarz 上界是 `|Δcos| ≤ ε = 0.1414`（最坏对齐），比间隙大 26 倍——那是上界，不是期望；
- 真正决定翻车率的是上面的 `ε/√d`，它**只是同一量级**，不是"大两个数量级"。

同样的量级关系也解释了第二个失败来源：grid 127 自身的量化误差范数约
`sqrt(d/12)/127 ≈ 0.0727`，恰为残差扰动的一半；分解到对上是"量化致败 ≈ 残余致败 ≈ 26pp，另有 21 对残差反而救回"。

### 4.4 加载基线：基并不总是"最像的那条记忆"

followup 录制的 120 个追问轮中，生产选基规则给出的基是：

| 基的来源 | 轮数 | 占比 |
|---|---|---|
| **同一 chunk 前半段的发现**（最相关） | 45 | 37.5% |
| 同一文件的另一条记录 | 52 | 43.3% |
| 另一条文件的记录 | 23 | 19.2% |

这是选基规则的机制性观察，属 P4-5/P5 的问题清单（本卡不改编码，卡面禁止改选基序）。

复算方式（只读录制与记忆库，不写任何东西）：对每个 `-b` 轮，取其 `baseMemoryId` 在
`<storage>/memory/<id>.json` 中的记录，比较该记录的 `taskTopic` 是否等于本轮 `path` 且 `summary` 是否等于
本 chunk（按 `chunkId` 从 `corpus/<id>/chunks.json` 取 `text`）的前半段 `slice(0, 400)`：
相等记"同一 chunk"，同 path 记"同一文件"，否则记"另一文件"。

## 5. 选定参数与理由

**选定：`grid = 127`，`threshold = 0.99`，布局 `int8` / stride 3。**

### 5.1 与卡面选点规则的偏离（必须显式声明）

卡面规则："一致性=100% 的组合中取平均字节最小者；无 100% 组合 → 取一致性最高档"。
按字面执行，最高档是 **grid=256 / int16 / threshold=0.99（2408.1 B，58.2%）**，而非选定点。

本卡的补充规则（**先说规则再看结果**）：取"与最高档在 0.05 容差内"的组合中最省字节者；容差用配对检验而非
总体差来判定。逐条数据：

| 记录 | 字面最高档（256/int16/0.99） | 选定点（127/int8/0.99） | 配对不一致 b:c | 配对差 | 95% CI（McNemar） | 精确双侧符号检验 | 平均载荷 |
|---|---|---|---|---|---|---|---|
| followup | 58.2% | 56.9% | 27 : 24 | +1.26pp | [−4.60, +7.11]pp | p = 0.780 | 2408.1 → **1789.73 B** |
| progression | 58.6% | 54.8% | 35 : 26 | +3.77pp | [−2.62, +10.15]pp | p = 0.306 | 2543.33 → **1905.82 B** |
| 合并 | — | — | 62 : 50 | +2.51pp | [−1.82, +6.84]pp | p = 0.299 | — |

（b:c 由随卡 JSON 的 `outcomes` 位集复算，位集即两个组合在每一对上的通过/不通过。b = 只有字面最高档通过的对数。）

**必须讲清的三件事，避免把这张表读成"统计等价"**：

1. **检验不显著 ≠ 等价。** 合并 CI 上界 +6.84pp，即本样本**排除不了** grid 256 真实更好约 7 个百分点。
   正确表述是"在 239 对（合并 478 对）的分辨率下无法判定谁更好"，而不是"两者一样好"。
2. **容差是 0.05，不是卡面隐含的 0。** 在 0.02 容差下，followup 仍选 127，但 progression 会选 256（54.8%
   距 58.6% 差 3.77pp）。两份录制在更严容差下**方向相反**，这一点在选点时必须一并披露。
3. **卡面规则本身没有容差条款**，所以本卡的选点是对卡面规则的**有据偏离**，不是它的执行结果。偏离的
   工程理由见 §5.2；如评审认为应回到字面规则，翻转成本仅是 §5.3 与 `delta-params.ts` 常量，测试会强制同步。

### 5.2 为什么便宜点还更安全

int8/stride3 的载荷结构上限是 `1024 × 3 = 3072 B`，**恒小于**它要替代的 4096 B float32 向量；
而 int16/stride4 的上限恰好是 4096 B，可能与全向量等长甚至不省。P4-4 的率失真选档条件
（"载荷必须小于完整向量"）在 int8 布局下是**结构性成立**的，不依赖运行时的数值偶然。加上 25.7% 的
实测载荷节省（1789.73 B vs 2408.1 B），选定点在"无法判定谁更准"的前提下严格更省。

## 6. 净收益结论（如实）

- **有序 top-5 一致性未达 100%，收益声明降级**（卡面明写的处置）。
- 载荷层面：选定点比完整向量少 **56.3%**（1789.73 B vs 4096 B），但这是**载荷**口径。
  P4-4 的全账口径还要加上基读取 object-io、编码/解码耗时与嵌入成本；**在 P4-4 计量完成前不得声称净收益为正**。
- 保真度层面：top-1 一致 97.9%、集合一致 79.1%。若下游只要求"检索到同一批材料"，集合口径可用；
  若要求名次完全一致，本机制在卡面扫描空间内**不达标**。
- 按计划 §8 的止损口径：若 P4-5 的全账对比不足，应走 spec §8.3 允许的出口——以 S2（完整向量）为参赛主实现，
  残差按"已实现待扩样"入档，并附本报告的成立条件。

## 7. 局限（评审须知，不得省略）

1. **前提依赖单一**：全部数字条件于单一 provider + 单一模型（SiliconFlow `BAAI/bge-m3`, dim 1024）
   + 40/8 窗口的 1238-chunk 语料。**该切块参数自己仍待学长确认**（§1.1）。前提一变，所有数字作废。
2. **语料近重复度高**：40/8 窗口使相邻块共享 32 行，rank-5/6 边界由近重复块主导——这正是有序判据苛刻的原因。
   若 G1 最终改用更粗窗口，**参数须在新快照上重标**。
3. **选基相似度偏低**（§4.4）：62.5% 的追问轮未选中同一 chunk 的前半段发现，实测 Y–B 余弦均值 0.71/0.64。
   真实部署若选基更准，载荷会更小、一致性会更高；本报告的数据是**当前选基规则**下的结果。
4. **样本量不足以做等效性判定**：§5.1 的 CI 仍容许字面最高档好 7pp。本卡据此只声明"无法判定"，
   不声明"等价"。若要真正判定，需扩样或在 P5 的正式序列上复核。
5. **录制不可比特级重放**：provider 不保证重嵌入逐比特一致，`pairs-*.jsonl` 是**录制产物**，
   `calibrate-delta.mjs` 的确定性针对的是"同一录制 → 同一报告"（实测两次运行逐字节相同，见 §8）。
6. **本卡不做全账计量**：信封、基 I/O、嵌入与回退成本属 P4-4，不在本报告数字内。
7. **判据口径**：主判据是有序 top-5（最严），同时给出 top-1 与集合口径。**卡面未规定三者中哪一个算"一致"**，
   本报告把三个都列出并明确选定主判据；评审如要改判据需重跑选点（脚本一次运行即可）。

## 8. 复现命令

```bash
cd D:\操作系统开源大赛\pi-share-agents

# 1) 录制（需 SILICONFLOW_API_KEY；已发布产物见 §1.2 的 sha256）
#    P3-3 的 build-corpus.mjs 单发路径在本 provider 下实测 3/4 次超时，
#    录制脚本内建重试包装（5 次、指数退避），成功批次走内存缓存不重发。
node experiments/legacy/record-delta-pairs.mjs --corpus-source <冻结快照目录> \
  --source-commit 3491b37ade90c863734e900b404144e19e274721 --mode followup \
  --storage-root <storage> --out <pairs-followup.jsonl> --rounds 240 \
  --window 40 --overlap 8

# 2) 标定（确定性：同一录制 → 同一报告）
node experiments/legacy/calibrate-delta.mjs --pairs <pairs-followup.jsonl> \
  --storage-root <storage> --out experiments/legacy/records/delta-calibration-20260919.json

# 3) 细 grid 天花板扫描（§4.2）
node experiments/legacy/calibrate-delta.mjs --pairs <pairs-followup.jsonl> --storage-root <storage> \
  --thresholds 0.90 --grids 127,256,512,1024,2048,4096,8192,16383 \
  --out experiments/legacy/records/delta-calibration-20260919-grid-ceiling.json

# 4) 0.05 容差下的 progression 选点（§5.1 第 2 点）
node experiments/legacy/calibrate-delta.mjs --pairs <pairs-progression.jsonl> --storage-root <storage> \
  --consistency-tolerance 0.05 --out experiments/legacy/records/delta-calibration-20260919-progression-tolerance.json

# 5) 报告表格回填（把 JSON 的表逐行写回本文件；幂等）
node experiments/legacy/fill-calibration-report.mjs
```

`--mode` 为必填：progression 与 followup 的相似度分布差异很大，录制不声明语域就无法互相比较。
录制脚本拒绝在非空记忆库上开始新录制（防止上一轮实验的记录污染本轮选基），`--append` 是唯一续录方式；
标定脚本拒绝含重复 roundId、或行内 corpusSnapshotId/representationId 与 header 不一致的录制文件
（防止两份录制被拼成一个混合文件后静默产生错误的参考排序）。
