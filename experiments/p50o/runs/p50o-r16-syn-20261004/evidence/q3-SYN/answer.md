## Answer

In `experiments/data/flask-src` (Flask `3.2.0.dev0`, detached HEAD `85c5d93cbd049c4bd0679c36fd1ddcae8c37b642`, reflog = clone + one checkout, no local commits; `../worktree/.build-manifest.json` pins the same `"flaskCommit"`), the separation is a **three-layer split — data in a shared base, behaviour duplicated in the two concrete components, registration funnelled into one app-side method** — and caching stays consistent because the duplicated behaviour is *two copies of the same algorithm reading the same global config*, not a shared implementation.

### Layer 1 — the shared base declares static *data*, not serving behaviour
`src/flask/sansio/scaffold.py`:
- `setupmethod` (:42-49) wraps every setup call with `self._check_setup_finished(f_name)`; the base raises `NotImplementedError` (:220-221) and each component overrides it — `sansio/app.py:413-417` fires on `_got_first_request`, `sansio/blueprints.py:213-217` on `_got_registered_once`.
- `class Scaffold` (:52, `versionadded:: 2.0`) is documented as "Common behavior shared between `Flask` and `Blueprint`"; its params include `static_folder` ("If this is set, a static route will be added") and `static_url_path` (:58-60).
- Static state lives here: `_static_folder` / `_static_url_path` (:72-73), `__init__(import_name, static_folder, static_url_path, template_folder, root_path)` (:78-88), `static_folder` property joining `root_path` (:224) and setter stripping trailing separators (:234), `has_static_folder` (:241), `static_url_path` property deriving `/{basename}` when unset (:249) and setter (:265).
- It *declares* the registration interface and does not implement it: `add_url_rule` with a full docstring ending in `raise NotImplementedError` (:368, :433).
- It holds **no caching hook**: a whole-file search of `scaffold.py` returns no `send_static_file` and no `get_send_file_max_age` (executor's `grep`, corroborated by `flask-src-scratch/mro_check.run-static-arch.txt`: `Scaffold defines send_static_file? False`, `Scaffold defines get_send_file_max_age? False`, `Scaffold defines has_static_folder? True`).

### Layer 2 — two component-specific mounts, one shared funnel
- **App side, eager at construction.** `class Flask(App)` (`app.py:81`); inside `Flask.__init__` (`app.py:267-279`) `if self.has_static_folder:` → `assert bool(static_host) == host_matching` → `self_ref = weakref.ref(self)` (avoiding the app↔view cycle, #3761) → `self.add_url_rule(f"{self.static_url_path}/<path:filename>", endpoint="static", host=static_host, view_func=lambda **kw: self_ref().send_static_file(**kw))`.
- **Blueprint side, deferred to registration.** `Blueprint.register` (`sansio/blueprints.py:273`) builds `state = self.make_setup_state(...)` and at :323-328 does `state.add_url_rule(f"{self.static_url_path}/<path:filename>", view_func=self.send_static_file, endpoint="static")` — the trailing `# type: ignore[attr-defined]` records that the method is not on the sansio class. `BlueprintSetupState.add_url_rule` (:87-116) prefixes the rule with `url_prefix` and rewrites the endpoint at :112 to `f"{self.name_prefix}.{self.name}.{endpoint}".lstrip(".")`, then calls `self.app.add_url_rule(...)` (:110). `Blueprint.add_url_rule` (:413) itself validates and `self.record(lambda s: s.add_url_rule(...))` (:434-440), which is exactly why blueprint static routes only exist after `register` runs.
- **Convergence.** Both paths end in `App.add_url_rule` (`sansio/app.py:605-661`): `rule_obj = self.url_rule_class(...)` (:650) → `self.url_map.add(rule_obj)` (:653) → overwrite guard (:658) → `self.view_functions[endpoint] = view_func` (:661). Endpoint naming therefore differs by design: app = `"static"` (`app.py:276`), blueprint = `{name_prefix}.{name}.static` (:112 × :327). The prior run shows `[('/static/<path:filename>', 'static')]` and `[('/admin/static/<path:filename>', 'admin.static')]`.

### Layer 3 — the caching contract is a duplicated contract, and *that* is what keeps it consistent
`app.py:281-305` and `blueprints.py:55-80` are two copies of `get_send_file_max_age` with byte-identical bodies (`value = current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]` at `app.py:298`; `None` → `None`; `timedelta` → `int(value.total_seconds())`; otherwise passthrough). `send_static_file` is likewise duplicated: `app.py:308-328` and `blueprints.py:82-102`, identical including the comment "send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too" and `max_age = self.get_send_file_max_age(filename)` → `send_from_directory(t.cast(str, self.static_folder), filename, max_age=max_age)`; both raise the same `RuntimeError` when `has_static_folder` is false (`app.py:320-321`). Both docstrings carry the sentence **"Note this is a duplicate of the same method in the Flask class."** — in `app.py:290-291`/`:314-315` that sentence sits *inside* `class Flask` and is self-referential; the executor confirmed via `git show HEAD:src/flask/app.py` plus a clean `git status --porcelain` that it **is upstream at `85c5d93`, not a local edit**.

So consistency across the two components rests on three concrete mechanisms, none of which is a shared base method: (i) two copies of the same algorithm; (ii) both copies reading the same global `current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]` (default `None` at `app.py:201`); (iii) both copies being mounted as the `"static"` view through the same `App.add_url_rule` funnel. The *interface* is per-component and overridable — `Scaffold` never defines it, so each subclass may replace it independently.

### Second plausible reading of the question
If "the main application framework" means the **concrete layer** rather than the app object, the same architecture answers it under a different framing: the `sansio/` modules hold the deferring/registering abstractions (`sansio/app.py:59 class App(Scaffold)`, `sansio/blueprints.py:34 BlueprintSetupState`, `:119 class Blueprint(Scaffold)`), while the concrete leaves `app.py:81 class Flask(App)` and `blueprints.py:18 class Blueprint(SansioBlueprint)` add the serving/caching methods. This is why `sansio/blueprints.py` can call `self.send_static_file` only under a `# type: ignore[attr-defined]`, and why the MRO probe prints `['Blueprint', 'Blueprint', 'Scaffold', 'object']` — two distinct classes share the name. Under either reading the separation is the same: shared base = static path data + the setup guard; leaves = the duplicated caching methods; `App.add_url_rule` = the one registration funnel.

### An adjacent mechanism that does **not** match the "consistent across both components" half
`flask.send_file` / `flask.send_from_directory` consult only the **app** hook: with `AppHook.get_send_file_max_age → 999` and a blueprint hook returning `100`, `send_from_directory(no max_age)` gave `max-age=999`, an explicit `max_age=42` bypassed the hook entirely, and `blueprint.send_static_file(...)` used `100` (`repro_static_architecture.py.run2-raw`, C8 checks). That is the app-only fallback path, deliberately *not* symmetric — the symmetry lives only in the static route pair.
