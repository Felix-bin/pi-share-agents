## Answer

The architecture is a **shared-base split**: one framework-agnostic registration class holds everything the two registered components have in common, while every serving decision is pushed down into each component's own WSGI class — and caching stays consistent because both components' serving code reads the *same* config key through the *same* hook.

**1. The shared base — `Scaffold`.** `src/flask/sansio/scaffold.py:52` declares `class Scaffold:` with the docstring "Common behavior shared between :class:`~flask.Flask` and :class:`~flask.blueprints.Blueprint`." What it owns is the *registration and configuration* surface: `setupmethod` (:38), `add_url_rule` (:368), the `static_folder` / `static_url_path` properties (:224, :249), `has_static_folder` (:241), `jinja_loader` (:274). What it does **not** own is serving — `Scaffold.__dict__` contains neither `get_send_file_max_age` nor `send_static_file`. The base is deliberately sans-io; the split is visible in the hierarchy: `src/flask/sansio/app.py:59 class App(Scaffold)` → `src/flask/app.py:81 class Flask(App)`, and `src/flask/sansio/blueprints.py:119 class Blueprint(Scaffold)` → `src/flask/blueprints.py:18 class Blueprint(SansioBlueprint)` (with `BlueprintSetupState` at `sansio/blueprints.py:34`). Runtime MROs confirm it: `Flask → [Flask, App, Scaffold, object]`, `Blueprint → [Blueprint, Blueprint, Scaffold, object]`. No other class in the tree derives from `Scaffold`.

**2. Serving implemented twice, once per component.** `Flask.send_static_file` (`src/flask/app.py:308-327`) and `Blueprint.send_static_file` (`src/flask/blueprints.py:82-101`) are byte-equivalent after stripping docstrings: guard on `has_static_folder`, else `RuntimeError("'static_folder' must be set to serve static_files.")`, then delegate to `send_from_directory`. Even the *registration* of the static route is component-specific: the app registers it eagerly in `Flask.__init__` (`app.py:267-279`, `endpoint="static"`, via a `weakref.ref(self)` lambda to avoid a reference cycle, per the `#3761` comment), while the blueprint registers it lazily at `Blueprint.register` time through the deferred setup state (`sansio/blueprints.py:323-327`) — `state.add_url_rule(f"{self.static_url_path}/<path:filename>", view_func=self.send_static_file, endpoint="static")`. So the shared base supplies `add_url_rule`, but each component decides when and how its own static route joins the app.

**3. What preserves caching consistency.** Three interlocking pieces:
- A single config key: `SEND_FILE_MAX_AGE_DEFAULT`, default `None`, declared once in `Flask.default_config` (`src/flask/app.py:201`).
- A single policy hook implemented identically on both components: `Flask.get_send_file_max_age` (`app.py:281-306`) and `Blueprint.get_send_file_max_age` (`blueprints.py:55-80`) are AST-equal (docstring stripped) and both read `current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]` (`app.py:298` / `blueprints.py:72`), normalise identically (`None` → `None`; `timedelta` → `int(value.total_seconds())` at `app.py:300,303-304` / `blueprints.py:74,77-78`; otherwise the raw value), and both resolve through `current_app`, not through `self` config.
- An explicit hand-off inside each `send_static_file`: `max_age = self.get_send_file_max_age(filename)` (`app.py:325`, `blueprints.py:99`) before passing `max_age` into `send_from_directory`, carrying the comment "send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too." That line is the whole reason blueprint static responses honour the app-level policy: the app's hook is what `send_file` would find, but the blueprint calls its own hook first, which reads the same app config. The fallback path agrees: `_prepare_send_file_kwargs` (`src/flask/helpers.py:389`) sets `kwargs["max_age"] = current_app.get_send_file_max_age` when nothing was passed, so plain `send_file` also routes through the app hook, and `docs/config.rst:250` documents the key and that it can be overridden "on the application or blueprint".

The targeted parity tests (`tests/test_helpers.py::TestSendfile::test_static_file`, `tests/test_blueprints.py::test_templates_and_static`, `tests/test_blueprints.py::test_default_static_max_age`) pass 3/3 in 0.20s when the worktree source is pinned; `test_default_static_max_age` (`tests/test_blueprints.py:226-244`) is the one that shows the per-component hook winning over the config value (subclass returns 100).
