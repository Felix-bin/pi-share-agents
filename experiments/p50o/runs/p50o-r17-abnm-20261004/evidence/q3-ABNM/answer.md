# Modular component registration architecture: static asset serving separated from the app framework, with caching held consistent

The separation has three parts, and caching consistency is **not** achieved by the shared base — it is achieved by duplication plus one shared config key.

**1. The shared base owns static *location*, not serving and not caching.** `Scaffold` (`src/flask/sansio/scaffold.py:53`, docstring: "Common behavior shared between :class:`~flask.Flask` and :class:`~flask.blueprints.Blueprint`") defines only `_static_folder` / `_static_url_path` (lines 72–73), the `static_folder` property/setter, `has_static_folder` → `self.static_folder is not None` (223–246), `static_url_path` (248–269) and `jinja_loader` (271–282). `get_send_file_max_age` and `send_static_file` are absent from it — a grep across `src/flask` returns those names only in `app.py`, `blueprints.py` and `helpers.py`.

**2. Two concrete components, one of them modular by deferred registration.** `Flask` and `Blueprint` each inherit `Scaffold` through a Sans-IO base (`src/flask/blueprints.py:20` `class Blueprint(SansioBlueprint)`; `CHANGES.rst` 3.0.0 "Restructure the code such that the Flask (app) and Blueprint classes have Sans-IO bases. :pr:`5127`"). The app registers its own static route eagerly in `Flask.__init__`: `if self.has_static_folder:` → `add_url_rule(f"{self.static_url_path}/<path:filename>", endpoint="static", host=static_host, view_func=lambda **kw: self_ref().send_static_file(**kw))` (`src/flask/app.py:263–278`). A blueprint instead adds nothing at import/definition time; the route is created inside `Blueprint.register`, when registration supplies the app's URL map: `if self.has_static_folder: state.add_url_rule(f"{self.static_url_path}/<path:filename>", view_func=self.send_static_file, endpoint="static")` (`src/flask/sansio/blueprints.py:322–327`). That callback is reached from `Flask.register_blueprint` → `blueprint.register(self, options)` (`src/flask/sansio/app.py:565`), and `BlueprintSetupState.add_url_rule` (87–113) applies the blueprint's `url_prefix` before delegating to `app.add_url_rule`. Hence the same blueprint can serve `/admin/static/...` under whatever prefix the app chose, without the app knowing about blueprint internals — the modularity is the deferral, not a separate server.

**3. Consistent caching is preserved deliberately, and the mechanism is duplication over a single source of truth.** Each component carries its own verbatim copy of `get_send_file_max_age` (`src/flask/app.py:281–304`, `src/flask/blueprints.py:55–78`); both docstrings state "Note this is a duplicate of the same method in the Flask class." Both bodies read the *same* key — `value = current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]`, converting `timedelta` via `int(total_seconds())` — so the two copies cannot diverge on the value they return. The static views are likewise parallel: `Flask.send_static_file` (`app.py:316–329`) and `Blueprint.send_static_file` (`blueprints.py:86–103`) each compute `max_age = self.get_send_file_max_age(filename)` and pass it to `send_from_directory(...)`, with the identical comment "send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too" (`app.py:323–324`, `blueprints.py:97–98`). The app-level fallback lives in `helpers._prepare_send_file_kwargs` (`src/flask/helpers.py:387–389`): `if kwargs.get("max_age") is None: kwargs["max_age"] = current_app.get_send_file_max_age` — it binds the *app's* method, which is exactly why a blueprint's view must resolve its own override first.

Execution confirms the two components agree in this worktree: with `SEND_FILE_MAX_AGE_DEFAULT = 1234` and the same static folder, `GET /static/css/test.css` and `GET /bp/static/css/test.css` both return `200 public, max-age=1234`, and with the config at `None` both return `no-cache` (executor, inline `test_client()` run). The three pinning tests pass (`tests/test_helpers.py::TestSendfile::test_static_file`, `tests/test_blueprints.py::test_templates_and_static`, `tests/test_blueprints.py::test_default_static_max_age` → 3 passed in 0.16s), and wider `-k "static or cache or max_age"` across those files selects only those three. Overrides are honoured per component: a `Flask` subclass returning 10 is honoured by both app and `flask.send_file`, and a `Blueprint` subclass returning 100 wins for the blueprint route even when app config differs (retriever, tests/test_helpers.py:44–90, tests/test_blueprints.py:224–244); docs state the same contract (`docs/blueprints.rst:191–217`, `docs/config.rst:250–262`).

**Contradiction flagged, not folded in.** `flask_mut2_i417ar2x/mutated_test.py` (the only untracked path in `git status --porcelain`) concerns subdomain routing — `subdomain_matching=False`, `SERVER_NAME`, `@app.route("/", subdomain="<company_id>")` — and has no bearing on static serving or caching.
