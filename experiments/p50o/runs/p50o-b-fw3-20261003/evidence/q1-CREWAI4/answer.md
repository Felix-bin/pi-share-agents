## Answer

**What `ensure_ascii` does in Flask.** It is a class-level default on `DefaultJSONProvider` — `ensure_ascii = True` at `src/flask/json/provider.py:144` — that the provider's `dumps` injects into stdlib `json.dumps` as a keyword default. The exact forwarding line is `kwargs.setdefault("ensure_ascii", self.ensure_ascii)` at `src/flask/json/provider.py:177`, immediately before `return json.dumps(obj, **kwargs)` at `:179`. Because it is `setdefault`, an explicit `ensure_ascii=` passed by the caller wins and the class attribute is not consulted; the class's own `dumps` docstring documents this forwarding ("Sets some parameter defaults from the :attr:`default`, :attr:`ensure_ascii`, and :attr:`sort_keys` attributes.", `:169-171`). The default is documented at `:145-148` as: "Replace non-ASCII characters with escape sequences. This may be more compatible with some clients, but can be disabled for better performance and size."

**Both representations, observed.** With `ensure_ascii=True` (the default), serializing a snowman through the provider returns the 8-character, pure-ASCII string `"\u2603"` — codepoints `0x22 0x5c 0x75 0x32 0x36 0x30 0x33 0x22`, `isascii() == True`, i.e. the non-ASCII codepoint is replaced by the six-character ASCII escape sequence `\u2603`, at the cost of size. With `ensure_ascii=False`, the same call returns the 3-character literal `"☃"` containing the single codepoint U+2603, `isascii() == False`. The observed outputs are identical to plain `json.dumps(..., ensure_ascii=...)` with the same setting, so the switch is exactly stdlib `json`'s `ensure_ascii` parameter, surfaced as a Flask provider default. The test suite parametrizes precisely this pair: `tests/test_json.py:48-54` sets `app.json.ensure_ascii` (`:52`) and asserts `'\\u2603'`-as-source vs. `'\u2603'`-as-source at `:49`, driving both through `app.json.dumps("\N{SNOWMAN}")` (`:53`). The parametrized test passed 2/2 (`2 passed in 0.03s`, exit status 0), and the one-liner through the provider reproduced both raw strings above at runtime.

**The encoding path that follows.** The provider itself never encodes: `DefaultJSONProvider.response` builds the body as a `str` — `f"{self.dumps(obj, **dump_args)}\n"` passed into `self._app.response_class(...)` with `mimetype=self.mimetype` (`src/flask/json/provider.py:213-215`). Leading-quote, the base `JSONProvider.response` does the same. Encoding to bytes happens in Werkzeug: `def _iter_encoded(iterable): for item in iterable: if isinstance(item, str): yield item.encode()` — `.encode()` with no argument, i.e. UTF-8 (`.venv/Lib/site-packages/werkzeug/wrappers/response.py:31-36`), with the class docstring stating the same ("The simple form is passing bytes, or a string which will be encoded as UTF-8.", `:44-46`). So `ensure_ascii=False` produces a literal non-ASCII character in the `str`, which is then delivered as UTF-8 bytes; there is no Flask-set `charset` attribute anywhere in `src/` or `tests/`. This UTF-8 link is the one part supported by cited source rather than by an executed observation — the response/`_iter_encoded` path was not exercised at runtime.

**It is a representation switch, not a semantic one.** `json.loads` returns the identical `"☃"` from both serializations (`round-trip equal: True`), so the parameter changes only how a codepoint is written into the serialized `str` — escaped ASCII sequence vs. literal UTF-8-bound character — not what value survives deserialization.

Paths that reach the same `dumps` and therefore inherit the default include `flask.json.dumps`, `jsonify`/bare dict returns (`src/flask/json/__init__.py:13-18`, `:138-145`) and Jinja's `json.dumps_function` policy (`src/flask/app.py:422`; Jinja's default kwargs supply no `ensure_ascii`). The attribute exists on `app.json` because `json_provider_class: type[JSONProvider] = DefaultJSONProvider` (`src/flask/sansio/app.py:230`, instantiated at `:329`); a provider that does not subclass `DefaultJSONProvider` would not have the attribute, and `tests/test_json.py:234-245` shows the substitution route to a custom provider.
