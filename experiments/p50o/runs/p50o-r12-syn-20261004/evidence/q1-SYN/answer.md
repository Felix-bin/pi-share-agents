## What the relationship is

**The switch selects the *representation* of an already-decided Unicode string on the wire; it never changes the value that the JSON encodes.**

- `DefaultJSONProvider.ensure_ascii = True` (`src/flask/json/provider.py:144`) — default **on**. Docstring `:145-147`: *"Replace non-ASCII characters with escape sequences. This may be more compatible with some clients, but can be disabled for better performance and size."* So the documented trade is compatibility vs size/perf, not correctness.
- Wiring: `dumps()` does `kwargs.setdefault("ensure_ascii", self.ensure_ascii)` (`:177`, between `:176` and `:178`) and returns `json.dumps(obj, **kwargs)` (`:179`); per-call kwargs win because it is `setdefault` (docstring `:169-171` "Sets some parameter defaults").
- Frozen by Flask's own tests: `tests/test_json.py:48-53` — `app.json.ensure_ascii = True` → `'"\\u2603"'`, `False` → the literal 3-char `"☃"` for the same input `"\N{SNOWMAN}"`. One input, two spellings, same code point.
- Reach: `response()` (`:202-216`) embeds `self.dumps(...)` in the body, so `/json` responses, `jsonify` and Jinja `tojson` inherit it; `tests/test_testing.py:110-114` shows `EnvironBuilder.json_dumps` doing the same (`ensure_ascii=False` writes literal UTF-8 euro bytes to the input stream).
- **Value invariance / one-way**: `loads()` (`:182-188`) is just `json.loads(s, **kwargs)` — no `ensure_ascii` on the decode side, so the flag is unreachable from deserialization and any RFC-8259 client decodes both spellings to the same string.
- **Direction and size**: escaping inflates the payload. For U+2603 the quoted form is 8 ASCII code units (`"\u2603"`) vs 3 (`"☃"`) — arithmetic from the frozen literals gives 8 vs 5 UTF-8 bytes — i.e. every BMP non-ASCII char costs 6 ASCII bytes escaped instead of 2–3 literal. Astral/surrogate-pair behaviour is not covered by any test I read (stdlib-level inference only).
- **Out-of-app-context path bypasses the provider**: module-level `flask.json.dumps` takes `json.dumps` when there is no `current_app` (`src/flask/json/__init__.py:42-45`), whose own default is `ensure_ascii=True` (`Lib/json/encoder.py:105`, and `:114-116`: "the output is guaranteed to be str objects with all incoming non-ASCII characters escaped"; `:193-196`, `:219-222` select `encode_basestring_ascii` vs `encode_basestring`). So `app.json.ensure_ascii = False` does **not** propagate there.
- History/scope: the attribute replaced the removed config key `JSON_AS_ASCII` (`CHANGES.rst:153-154`, `:285-288`; `docs/config.rst:417-443`).
