**2. Route registration (test lines 307–309)**

**3. Request-context creation and the adapter it depends on (test lines 311–315)**
- `with app.test_request_context():` → `app.py:1423` `test_request_context` → `testing.EnvironBuilder(self, ...)` then `builder.get_environ()` → `app.request_context(environ)` (`app.py:1407`) → `RequestContext(self, environ)` (`ctx.py:309`).
- `RequestContext.__init__` immediately calls `app.create_url_adapter(self.request)` (`ctx.py:326`); the push path also calls `match_request()` (`ctx.py:389-390` → `ctx.py:357-362`, `self.url_adapter.match(return_rule=True)`).
- `create_url_adapter` (`app.py:425`) is the joint the whole chain hangs on: because `subdomain_matching` is `True`, `subdomain` stays `None` and `url_map.bind_to_environ(request.environ, server_name="example.com", subdomain=None)` is called (`app.py:463-466`). Werkzeug then derives `subdomain = ""` from host `example.com` vs. `SERVER_NAME` (`werkzeug/routing/map.py:316-341`).
- `flask.url_for("view", company_id="xxx")` → `helpers.py:188-235` → `Flask.url_for` (`app.py:1003`), which takes `req_ctx.url_adapter` (`app.py:1058-1061`) and calls `url_adapter.build(..., force_external=False)`. The build shortcut at `werkzeug/routing/map.py:944-948` is *not* taken, because the rule's resolved `domain_part` (`xxx`) differs from the adapter's `subdomain` (`""`), so the short-circuit instead returns the absolute `http://xxx.example.com/` (`map.py:950-951`) — this is why the test can hand `url` straight to the client.
- `client.get(url)` → `FlaskClient.open` / `_request_from_builder_args` (`testing.py:193-236`) → `EnvironBuilder` uses `url.netloc` as the host (`testing.py:66-80`), so `HTTP_HOST = xxx.example.com`; `wsgi_app` → `request_context` → `create_url_adapter` again, now with a host that yields subdomain `xxx`, and the rule registered in step 2 matches, returning `b"xxx"` with status 200.

So the dependency direction is: `subdomain_matching` flag + `SERVER_NAME` → rule with a subdomain → request-context URL adapter bound with `server_name`/`subdomain` → `url_for` emitting the subdomain host → client request matching the subdomain rule. Break the first link and the whole chain fails; nothing downstream can compensate.
