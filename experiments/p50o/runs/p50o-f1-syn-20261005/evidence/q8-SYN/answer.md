## How static asset serving is factored across the modular components

Flask splits the concern in two layers, both rooted in the Sans-IO base class `Scaffold`:

1. **Shared configuration base — `flask/sansio/scaffold.py:52 class Scaffold`**, documented as "Common behavior shared between `Flask` and `Blueprint`". It owns everything about *where* static assets are: `static_folder` (returns the absolute path joined to `root_path`, lines 224–238), `has_static_folder` (241–246), and `static_url_path`, which when unset is derived identically for both components from the folder basename (248–266). Because both components inherit this, the app and the blueprints cannot disagree on static-folder path semantics or default URL prefix.

2. **Two concrete components built on that base:**
   - main framework: `src/flask/sansio/app.py:59 class App(Scaffold)` → `src/flask/app.py:81 class Flask(App)`
   - modular component: `src/flask/sansio/blueprints.py:119 class Blueprint(Scaffold)` → `src/flask/blueprints.py:18 class Blueprint(SansioBlueprint)`
   This is the split recorded in `CHANGES.rst` under 3.0.0: "Restructure the code such that the Flask (app) and Blueprint classes have Sans-IO bases. :pr:`5127`". `src/flask/sansio/README.md` states the rule that makes the split work: sansio code "cannot do any IO, nor be part of a likely IO path" and "cannot use the Flask globals".

3. **Static routes are registered separately by each component into one URL map:**
   - The app registers its own rule eagerly in `Flask.__init__` (`src/flask/app.py:267–279`): rule `f"{self.static_url_path}/<path:filename>"`, `endpoint="static"`, view function a weakref dereference to `send_static_file` (to avoid the app↔view reference cycle, #3761). It does this whether or not the folder exists on disk, so a folder created later is served.
   - A blueprint registers its own rule only at `register_blueprint` time: `src/flask/sansio/blueprints.py:323–327`, inside `Blueprint.register`, calls `BlueprintSetupState.add_url_rule` (`sansio/blueprints.py:87–115`), which prefixes the rule with the blueprint's `url_prefix`, defaults `subdomain` to the blueprint's, and prefixes the endpoint with the blueprint name — so the endpoint becomes `blueprint_name.static` while the app's stays `static`. `docs/blueprints.rst:191–210` documents the outcome (`/admin/static/...`, `url_for('admin.static', filename='style.css')`).

4. **Caching consistency is preserved by duplicating the hook, not by inheriting it.** `get_send_file_max_age` exists twice, byte-for-byte equivalent: `Flask.get_send_file_max_age` (`src/flask/app.py:281–305`) and `Blueprint.get_send_file_max_age` (`src/flask/blueprints.py:55–79`). Both read `current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]`, convert a `timedelta` to seconds, and otherwise return the value (`None` by default, meaning conditional requests rather than a timed cache; default registered at `src/flask/app.py:201`). `send_static_file` is likewise duplicated (`app.py:308–327`, `blueprints.py:82–101`) and carries the line that explains the whole arrangement: *"send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too."* Both implementations therefore compute `max_age = self.get_send_file_max_age(filename)` themselves and pass it explicitly into `send_from_directory`. The helper path has the app-side fallback: `_prepare_send_file_kwargs` in `src/flask/helpers.py:386–388` sets `kwargs["max_age"] = current_app.get_send_file_max_age` when `max_age` is `None`. Net effect: the config key is global, the hook is per-component, and a component-level override (e.g. a `Blueprint` subclass) governs that component's static route while direct `send_file`/`send_from_directory` calls still follow the app.

5. **The separation is per-rule, not a fallback chain** — a documented asymmetry rather than a bug: `docs/blueprints.rst:212–217` states that a blueprint with no `url_prefix` cannot expose its static folder because its URL would be `/static`, where "the application's `/static` route takes precedence", and "unlike template folders, blueprint static folders are not searched if the file does not exist in the application static folder."
