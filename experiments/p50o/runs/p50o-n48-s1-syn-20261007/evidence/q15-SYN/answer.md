# How `CertParamType.convert` implements the fallback chain

The `--cert` option uses `type=CertParamType()` (`src/flask/cli.py:885-889`), whose `convert` (`src/flask/cli.py:791-825`) is not a dispatch on value shape but a **sequential `try`/`except` cascade**: each stage is entered only because the previous one failed, and the value is reinterpreted at each step. The class docstring states the three accepted forms — "an existing file, the string `'adhoc'`, or an import for a `ssl.SSLContext` object" (`cli.py:781-784`), with `name = "path"` (`cli.py:786`) as the user-visible type label.

The stages, in order:

1. **SSL availability guard** — `cli.py:795-801`: `import ssl` inside `try`; on `ImportError`, `click.BadParameter('Using "--cert" requires Python to be compiled with SSL support.', ctx, param)`. Nothing else can run in this process without `ssl`, so this gate precedes the whole chain.
2. **Stage 1 — strict file path** — `cli.py:803-804`: `return self.path_type(value, param, ctx)`, where `self.path_type = click.Path(exists=True, dir_okay=False, resolve_path=True)` is built in `__init__` (`cli.py:788-789`). A value naming an existing, non-directory file is returned immediately as a resolved absolute path — the chain ends here. Anything else raises `click.BadParameter`, which is what admits the rest of the chain.
3. **Reinterpretation, not a new attempt** — `cli.py:805-806`: `except click.BadParameter:` then `value = click.STRING(value, param, ctx).lower()`. The raw value is coerced to a string and lowercased, so all subsequent string matching (including `"adhoc"`) is case-insensitive, and the dotted import path is looked up in lowercase form.
4. **Stage 2 — the `adhoc` literal** — `cli.py:808-818`: `if value == "adhoc":` is itself gated: `import cryptography` in a `try`, and on `ImportError` it raises `BadParameter("Using ad-hoc certificates requires the cryptography library.", ctx, param)`. If the import succeeds it returns `value`, i.e. the literal string `"adhoc"` — the placeholder the server layer later turns into a generated certificate.
5. **Stage 3 — dotted-path import of an `SSLContext`** — `cli.py:820-823`: `obj = import_string(value, silent=True)` (silent, so a failed import yields `None` rather than raising), then `if isinstance(obj, ssl.SSLContext): return obj`. Only an actual `ssl.SSLContext` object is accepted; a successfully imported module that is not an `SSLContext` falls through.
6. **Terminal failure re-raises the first stage's error** — `cli.py:825`: a bare `raise` still inside the `except click.BadParameter:` block, which re-raises the original `click.Path` `BadParameter`. Consequently an unrecognised value such as `--cert not_here` produces the file-path/not-found error, not a message about strings or imports. There is no branch that raises a string-specific "invalid value" error.

So the three documented outcomes are produced by three different stages of one cascade: resolved path string (stage 1), `"adhoc"` (stage 2, plus the `cryptography` guard), `SSLContext` instance (stage 3, plus the `isinstance` filter).

**Adjacent consumption of the chain's result.** `_validate_key` (`cli.py:828-864`) is the `callback` of `--key` (`cli.py:891-897`) and keys off the already-converted `cert`: `is_adhoc = cert == "adhoc"` (`cli.py:833`), `is_context = isinstance(cert, ssl.SSLContext)` (`cli.py:836-840`). It rejects `--key` with `'When "--cert" is "adhoc", "--key" is not used.'` (`843-846`) and with `'When "--cert" is an SSLContext object, "--key" is not used.'` (`848-853`), requires `--cert` when only `--key` is given (`855-856`), and only for a file-path cert rewrites `ctx.params["cert"] = cert, value` into a `(cert, key)` pair (`cli.py:858`). The `--cert` option's `is_eager=True` (`cli.py:889`) is what makes this ordering independent of the order the two flags appear on the command line.

**Behaviour pinned by the test suite** (`tests/test_cli.py:584-648`), one test per stage: `test_run_cert_path` (`584`) — path stage and the `(cert, key)` pairing in both flag orders; `test_run_cert_adhoc` (`602`) — `BadParameter` without `cryptography`, `"adhoc"` with it, `--cert adhoc --key __file__` rejected; `test_run_cert_import` (`619`) — a missing module and a non-`SSLContext` module (`flask`) raise `BadParameter`, a registered `ssl.SSLContext` is returned identically (`is ssl_context`), and it rejects `--key`; `test_run_cert_no_ssl` (`641`) — with `sys.modules["ssl"] = None`, any `--cert` raises, confirming the guard in step 1 fires before any fallback.

Basis: `src/flask/cli.py` (read at `780-899`, line numbers confirmed by grep) and `tests/test_cli.py` (read at `584-648`); the retriever's report on the same ranges, which matched the file exactly.

Open / carrying uncertainty: the literal wording of `click.Path`'s `BadParameter` was not read, so the *exact text* the user sees for an unrecognised `--cert` value is inferred from the bare `raise` at `cli.py:825` rather than observed; the lowercasing's effect on import lookup (`cli.py:806` → `820`) follows from the code but is not covered by any test. Nothing else in the question — the ordering, the return value of each stage, and the guards — is left unresolved.
