# `copy_current_request_context`: isolation across concurrent execution contexts, and session preservation

`flask.copy_current_request_context` (`src/flask/ctx.py:155-193`, exported at `src/flask/__init__.py:6`) does two distinct things, and the split explains both halves of the question: it **copies the context object once at decoration time**, and it lets **ContextVar token binding** — not the copy — do the isolation work.

**1. The snapshot happens at decoration time.** Inside the view, `ctx = _cv_request.get(None)` (`ctx.py:179`) grabs the currently bound request context; if nothing is bound the decorator raises `RuntimeError("'copy_current_request_context' can only be used when a request context is active, such as in a view function.")` (`ctx.py:181-184`); then `ctx = ctx.copy()` (`ctx.py:187`) freezes that snapshot. The returned wrapper (`ctx.py:189-191`) is `with ctx: return ctx.app.ensure_sync(f)(*args, **kwargs)` — every invocation re-enters *the same copied object*, and routing through `ensure_sync` means async callables are driven correctly too.

**2. Isolation comes from per-execution-context ContextVar bindings.** The process-wide state is two ContextVars, `_cv_app` and `_cv_request` (`src/flask/globals.py:24,42`), which back the `request`, `session`, `request_ctx`, `current_app` and `g` proxies. `RequestContext.push` records `self._cv_tokens.append((_cv_request.set(self), app_ctx))` (`ctx.py:367-390`) and `pop` restores the previous binding via `_cv_request.reset(token)` while asserting identity — *"Popped wrong request context"* (`ctx.py:396-430`). Because a ContextVar binding belongs to the executing greenlet/task rather than to the process, a greenlet spawned by the view sees `flask.request` and `flask.current_app` unbound *before* it enters `with ctx:`, sees them bound and pointing at the view's request *inside* the block, and sees them unbound again *after* it exits — while the spawning request keeps its own binding undisturbed. `push` also reuses the parent's app context when `_cv_app.get(None)` is already set for the same app, recording `app_ctx = None` so the child's `pop` does not tear down the parent's app context (`ctx.py:370-378`).

**3. Session preservation is a consequence of *what* `copy()` passes, plus a guard in `push()`.** `RequestContext.copy()` (`ctx.py:337-354`) builds a new context over the *same* request and environ and, since the `versionchanged:: 1.1` note, `session=self.session` — the already-loaded live session object rather than a reload. On the copy's `push`, the session-opening branch is guarded by `if self.session is None:` (`ctx.py:384`), and the code comment states the reason outright: *"Only open a new session if this is the first time the request was pushed, otherwise stream_with_context loses the session"* (`ctx.py:382-383`). So `session_interface.open_session` is never called for the copy, and `flask.session["fizz"] = "buzz"` set in the view resolves to `"buzz"` inside the greenlet. The same docstring deliberately scopes the mechanism: it *"can be used to move a request context to a different greenlet"* but *"cannot be used to move a request context to a different thread unless access to the request object is locked"* — the copy is shallow, sharing the request object by reference. A derived consequence, stated as derived: since the session is literally the same object, mutations made *through the copy* are visible to the original context as well; no in-tree code asserts that direction.

**4. The neighbouring helper shows the alternative.** `stream_with_context` (`src/flask/helpers.py:62-115`) uses the identical `ctx = _cv_request.get(None)` + `with ctx:` shape and the identical no-active-context `RuntimeError`, but on the **original** context — it nests token bindings on one context object instead of copying. It is the other "context survives an execution boundary" mechanism, and the `push()` comment above is written with it in mind.

- **Rests on:** `src/flask/ctx.py:155-193` (decorator body, decoration-time snapshot, wrapper), `:337-354` (`copy()` sharing request/environ/session), `:367-390` (`push`, app-context reuse, session guard and comment), `:396-430` (`pop`, token reset, wrong-context assertion); `src/flask/globals.py:24,42` (the two ContextVars and their proxies); `src/flask/helpers.py:62-115` (`stream_with_context` contrast); `src/flask/__init__.py:6` (public export); `tests/test_reqctx.py:147-202` (assertions and skip guard); executor run results (exit 0, 2 passed, interpreter/greenlet/pytest versions, `flask.__file__` check).
- **Runner caveat:** a bare `python -m pytest` cannot run these tests here — collection fails with `ModuleNotFoundError: No module named 'flask'` because the venv's `flask.pth` names a different worktree's `src`; `PYTHONPATH=src` had to be pinned. Any future run should pin the same way.
- **Open:** only 2 of the 14 tests in `tests/test_reqctx.py` were run — no wider-suite result, and no asyncio-task variant of the isolation claim was executed (that part rests on ContextVar semantics and on `copy()` sharing request/environ, not on a measured asyncio run). The reverse-direction session sharing (copy → original) is inferred from `copy()`'s arguments; the `versionchanged:: 1.1` note is the only in-tree statement of intent for sharing the live session object.
