## The dependency chain

The test function is **`tests/test_testing.py::test_subdomain`** (lines 302–319) — it is the only test that builds *all three* elements: `SERVER_NAME` + `subdomain_matching` configuration, a subdomain route registration, and explicit request contexts. Its module-level twin is `flask_mut2_i417ar2x/mutated_test.py`, identical except `subdomain_matching=True` → `False`.

The chain is strictly ordered; each link consumes what the previous one produced:

1. **Configuration → host + matching switch.** `flask.Flask(__name__, subdomain_matching=True)` (302/303) and `app.config["SERVER_NAME"] = "example.com"` (304).
   - `SERVER_NAME` is what gives the test client/context builder its host: `http_host = app.config.get("SERVER_NAME") or "localhost"` (`src/flask/testing.py:66`).
   - `subdomain_matching` is consumed only later, at URL-adapter creation: when it is false, Flask pins the adapter subdomain to `self.url_map.default_subdomain or ""` instead of letting Werkzeug derive it from the request host (`src/flask/app.py:451–466`).
   - The test takes **no pytest fixtures** (contrast the sibling `test_nosubdomain(app, client)` at 321), so "dependency chain" here means these internal data/control links, not a fixture graph.
2. **Route registration → addressability.** `@app.route("/", subdomain="<company_id>")` on `view` (306–308). This is the only rule for `/`, and its subdomain pattern is the thing link 4 must satisfy.
3. **First request context → URL that carries the subdomain.** `with app.test_request_context(): url = flask.url_for("view", company_id="xxx")` (310–311).
   - The context supplies the adapter `Flask.url_for` uses (`req_ctx.url_adapter`, `src/flask/app.py:1069–1071`); its host comes from `SERVER_NAME` (`testing.py:65–66`), i.e. `example.com` with adapter subdomain `""`.
   - Because the built rule's subdomain (`"xxx"`) differs from the adapter's (`""`), Werkzeug skips its same-subdomain shortcut and emits the absolute URL `http://xxx.example.com/` (`werkzeug/routing/map.py:943–947`; docstring at 841–844: external URLs are used when the target is on a different subdomain). So link 3 output = path **plus** the subdomain link 4 will be matched against.
4. **Second request context → replay through routing.** `with client: response = client.get(url)` (313–314). The absolute URL becomes the request host `xxx.example.com`; routing resolves `xxx` from the host, matches the `<company_id>` rule, and `view("xxx")` returns `"xxx"` with status 200.
5. **Assertions → end-to-end verification.** `assert 200 == response.status_code` and `assert b"xxx" == response.data` (316–317) are satisfied only if all of 1–4 held.

**Where the chain is designed to break.** In `flask_mut2_i417ar2x/mutated_test.py` only link 1 changes (`subdomain_matching=False`). Link 3 still yields `http://xxx.example.com/`, since the request-context adapter's subdomain is `""` either way; the break is at **link 4**: Flask forces the adapter subdomain to `""` for the incoming `xxx.example.com` request (`app.py:458–462`), the `"xxx"` rule cannot match, the view never runs, and the response is 404 — so the first assertion fails. This is a derivation from those two source sites (I have no shell in this role to re-run it), and it is consistent with the recorded run state in the working directory: `.pytest_cache/v/cache/lastfailed` lists `"flask_mut2_i417ar2x/mutated_test.py": true`, while `tests/test_testing.py::test_subdomain` appears in `nodeids` (collected) and *not* in `lastfailed`. The mutated file lives outside the default suite (`pyproject.toml:107–108`, `testpaths = ["tests"]`), so it only runs when invoked explicitly.

The same chain appears in weaker/adjacent forms elsewhere — `tests/test_basic.py::test_subdomain_basic_support` (1754), `test_subdomain_matching` (1774), `test_subdomain_matching_with_ports` (1787), `tests/test_testing.py::test_blueprint_with_subdomain` (117, which passes `subdomain="xxx"` to `test_request_context` rather than deriving it from a URL), and `tests/test_reqctx.py::test_proper_test_request_context` (64, config + registration + `test_request_context`, but asserting `url_for` output instead of a request round-trip).
