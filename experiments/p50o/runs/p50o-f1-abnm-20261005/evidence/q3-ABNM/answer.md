## The modular component registration architecture is blueprints

Flask's modular unit is the **blueprint**: `docs/blueprints.rst:5-12` states "Flask uses a concept of *blueprints* for making application components", and `src/flask/sansio/blueprints.py:129-135` defines a blueprint as "a collection of routes and other app-related functions that can be registered on a real application later… records them for later registration". The app object and the blueprint object are the two "components" in your question; they share a registration surface and each owns its own static-file view.

### 1. Registration pipeline (deferred, then merged)

- `Scaffold` (`src/flask/sansio/scaffold.py:60-73`) is the common base holding the shared knobs both components expose: `static_folder`, `static_url_path`, `has_static_folder`, and `root_path`. Both `App` (`src/flask/sansio/app.py:285-297`) and `Blueprint` (`src/flask/sansio/blueprints.py:171-195`) build on it.
- A blueprint does not touch the app while being defined. API calls are appended as deferred callbacks (`Blueprint.record` / `record_once`, `src/flask/sansio/blueprints.py:236-268`), with `Blueprint.add_url_rule` recording `lambda s: s.add_url_rule(...)` (`src/flask/sansio/blueprints.py:426-451`).
- `app.register_blueprint(bp, **options)` (`src/flask/sansio/app.py:569-584`) delegates to `Blueprint.register(app, options)` (`src/flask/sansio/blueprints.py:283-410`). That method builds a `BlueprintSetupState`, rejects duplicate names, merges error handlers/view functions/callbacks into the app, and replays the deferred functions. `BlueprintSetupState.add_url_rule` (`src/flask/sansio/blueprints.py:94-128`) is what actually reaches the app: it joins the `url_prefix`, applies the subdomain, and prefixes the endpoint with `"{name_prefix}.{name}.{endpoint}"`. Nested blueprints get combined url prefixes and dotted name prefixes by the same method (`src/flask/sansio/blueprints.py:377-409`), and `register_blueprint` on a blueprint raises on `blueprint is self` (`src/flask/sansio/blueprints.py:270-282`).

### 2. Static asset serving is a route owned by each component, not by the framework

Neither component's static handling lives in the router/framework layer; each component registers a view and delegates the actual byte-serving to the same helper (`flask.helpers.send_from_directory` → Werkzeug `send_file`, `src/flask/helpers.py:531-556`):

- App: `Flask.__init__` registers `f"{self.static_url_path}/<path:filename>"` with `endpoint="static"` and a view function that is a **weakref** to the app calling `self.send_static_file(**kw)` (`src/flask/app.py:262-279`; the comment cites issue #3761 and the reference-cycle reason for the weakref). Registration happens unconditionally when `has_static_folder`, deliberately without checking that the folder exists (`src/flask/app.py:264-267`).
- Blueprint: `Blueprint.register` registers the same-shaped rule only **at registration time** and only `if self.has_static_folder`: `f"{self.static_url_path}/<path:filename>"`, `view_func=self.send_static_file`, `endpoint="static"` (`src/flask/sansio/blueprints.py:322-327`). Because the setup state prefixes the endpoint, it becomes `<blueprint_name>.static`, reachable as `url_for("admin.static", filename="style.css")` (`docs/blueprints.rst`, "Static Files"; asserted in `tests/test_blueprints.py:209-213`).
- Both views raise `RuntimeError("'static_folder' must be set to serve static_files.")` when `static_folder` is unset (`src/flask/app.py:320-321`, `src/flask/blueprints.py:94-95`), and both delegate to `send_from_directory` with `t.cast(str, self.static_folder)`.

### 3. How caching stays consistent across both components

The glue is that the max-age decision is a **method on each component**, reading the **same app config key**, and the blueprint deliberately resolves it before delegating:

- `Flask.get_send_file_max_age` (`src/flask/app.py:281-306`) and `Blueprint.get_send_file_max_age` (`src/flask/blueprints.py:55-79`) are byte-for-byte the same logic: read `current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]`, return `None` if unset, convert a `timedelta` to `int(total_seconds())`, otherwise return the int. Both docstrings say explicitly "Note this is a duplicate of the same method in the Flask class" — the consistency is maintained by duplication against one shared config value, not by inheritance.
- The default is `None` (`src/flask/app.py:201`), which per `docs/config.rst:250-258` tells the browser to use conditional requests rather than a timed cache; the config may be an `int` or `timedelta`, and is overridable per file via `get_send_file_max_age` "on the application or blueprint".
- Why the duplication is load-bearing: `flask.helpers._prepare_send_file_kwargs` falls back to `kwargs["max_age"] = current_app.get_send_file_max_age` whenever `max_age is None` (`src/flask/helpers.py:387-389`) — i.e. the send path only ever knows about the **app's** method. So `Blueprint.send_static_file` resolves `max_age = self.get_send_file_max_age(filename)` first and passes it in explicitly, with the in-code comment: "send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too" (`src/flask/blueprints.py:96-102`). That single line is what makes a blueprint subclass's override win: `tests/test_blueprints.py:225-245` subclasses `Blueprint` with `get_send_file_max_age` returning 100, sets the app config to a different value, and asserts `Cache-Control: max-age=100`; `tests/test_blueprints.py:194-207` asserts the app-level config value reaches the blueprint static route.

### 4. Documented precedence caveat

A blueprint with a `static_folder` but **no** `url_prefix` exposes `/static`, which collides with the app's static route; the app's route takes precedence and "it is not possible to access the blueprint's static folder" — unlike templates, blueprint static folders are not searched as a fallback (`docs/blueprints.rst`, "Static Files"; also `src/flask/sansio/blueprints.py:144-147`). Blueprint static is off by default (`static_folder=None`), consistent with `src/flask/sansio/blueprints.py:139-143`.
