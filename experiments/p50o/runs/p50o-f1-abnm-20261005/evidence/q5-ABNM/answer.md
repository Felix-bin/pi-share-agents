## Dependency chain in `test_subdomain` (tests/test_testing.py:302-318)

The test is `test_subdomain`. Its chain is a single linear causal path from application configuration to the assertion, and every link is load-bearing:

1. **Configuration, part 1 — the matching flag.** `flask.Flask(__name__, subdomain_matching=True)` (tests/test_testing.py:303). This is what lets a subdomain rule participate in matching at all: when it is false, `create_url_adapter` overwrites the request's subdomain with `self.url_map.default_subdomain or ""` (src/flask/app.py:458-462), so the request can never present the subdomain the rule needs.
2. **Configuration, part 2 — the server name.** `app.config["SERVER_NAME"] = "example.com"` (tests/test_testing.py:304). This is the name the URL adapter binds to and the host that `url_for` prepends the target subdomain to (src/flask/app.py:450-467; src/flask/testing.py:64-77). Without it the adapter still binds from the request host, but the generated host is the builder's `localhost` default rather than `example.com` (src/flask/testing.py:65).
3. **Client construction.** `client = app.test_client()` (tests/test_testing.py:305). Its environ is built per request by `EnvironBuilder`, which reads `SERVER_NAME`, `APPLICATION_ROOT` and `PREFERRED_URL_SCHEME` at call time (src/flask/testing.py:64-77) — so this call does *not* have to come after the config, and tests/test_basic.py:1545 in fact mutates `SERVER_NAME` after `test_client()` and expects it to take effect.
4. **Route registration.** `@app.route("/", subdomain="<company_id>")` on `def view(company_id)` (tests/test_testing.py:307-309). This does two things in the chain: it creates the endpoint `"view"` that `url_for` must find (otherwise `BuildError`), and it gives the rule a *domain part* `"xxx"` that differs from the current request's subdomain. Both are needed below.
5. **Request context creation.** `with app.test_request_context():` (tests/test_testing.py:311), deliberately with **no** `subdomain=` argument. The environ therefore has `http_host = "example.com"`, the current subdomain is `""`, and `RequestContext.__init__` sets `self.url_adapter = app.create_url_adapter(self.request)` (src/flask/ctx.py:323). This step is what makes step 6 possible: `flask.url_for` outside any context needs an app-context adapter and raises `RuntimeError("Unable to build URLs outside an active request without 'SERVER_NAME' configured…")` if it cannot get one (src/flask/app.py:1089-1093).
6. **URL building — where the context and the rule meet.** `url = flask.url_for("view", company_id="xxx")` (tests/test_testing.py:312). Inside a request, `_external` defaults to `False` (src/flask/app.py:1076-1077), but Werkzeug's shortcut returns a bare path only when the rule's domain part equals the adapter's subdomain (werkzeug/routing/map.py:943-948). Here `"xxx" != ""`, so the shortcut is skipped and the external URL `http://xxx.example.com/` is produced. The request context is thus not merely a place to call `url_for` from — its empty subdomain is the reason the URL comes out absolute.
7. **Dispatching the built URL.** `with client:` / `response = client.get(url)` (tests/test_testing.py:314-315). Because `url` is absolute, `EnvironBuilder` derives `HTTP_HOST = xxx.example.com`; with `subdomain_matching=True` `bind_to_environ` extracts subdomain `"xxx"` (src/flask/app.py:457-467), which matches the `<company_id>` converter, so `view` runs with `company_id="xxx"`.
8. **Assertions.** `200` and `b"xxx"` (tests/test_testing.py:317-318) — the payload is the converted subdomain itself, so the assertion consumes step 7 and, transitively, every earlier link.

In one line: **matching flag + `SERVER_NAME` → `test_client` → subdomain rule registered under endpoint `view` → `test_request_context()` supplying an adapter whose subdomain is `""` → `url_for` forced to build the external `http://xxx.example.com/` → `client.get` of that URL matches the rule → status/data assertions.**
