**Scope first, because it changes the answer.** The corpus handed to me is a vendored **Flask 3.2.0.dev** tree (`experiments/data/flask-src/pyproject.toml:2-3` `name = "Flask"`, `version = "3.2.0.dev"`; an identical second copy also sits at `experiments/data/worktree/flask`). That scope call belongs to the parent; the answer below is for the Flask copy.

**The relationship.** The ASCII-only control is `ensure_ascii`, a class attribute of the provider (`src/flask/json/provider.py:144` `ensure_ascii = True`, docstring `:145-148`: *"Replace non-ASCII characters with escape sequences. This may be more compatible with some clients, but can be disabled for better performance and size."*). It does not touch Unicode values through the public response path directly — it is injected into `json.dumps` as a default, and Python's encoder then *selects a different string encoder*, so the flag changes the **serialized representation of every string, in both values and keys**, while leaving the decoded value identical.

**Mechanism, step by step (all file:line):**
1. Injection — `provider.py:177` `kwargs.setdefault("ensure_ascii", self.ensure_ascii)` inside `DefaultJSONProvider.dumps` (`:167-179`); the class value is applied **only when the caller omitted the keyword**, so an explicit `app.json.dumps(obj, ensure_ascii=False)` wins. `DefaultJSONProvider.response` (`:213-215`) passes only `indent`/`separators`, so HTTP responses always follow the attribute. `grep ensure_ascii` over the tree returns 5 hits only (`provider.py:144,171,177`; `tests/test_json.py:52`; `tests/test_testing.py:112`) — nothing in `src/` overrides the attribute.
2. Encoder branch — CPython `json/encoder.py:193-196` (str) and `:219-222` (`_encoder = encode_basestring_ascii` when true, `encode_basestring` when false); the selected `_encoder` is consumed at `:301` (list items), `:387` (**dict keys**), `:391` (dict values), `:426` (top level).
3. Representation — with the flag true, the regex `ESCAPE_ASCII = re.compile(r'([\\"]|[^\ -~])')` (`encoder.py:19`) escapes everything outside `0x20`–`0x7E`: BMP as `\uXXXX` (`:59-60`), astral as a UTF-16 **surrogate pair** (`:62-67`, `\ud83d\ude00`). With it false, the characters are emitted literally into the returned `str`.

**Observed (executed, CPython 3.14.0 stdlib, not Flask):** `json.dumps({"a":"☃","☃key":1,"e":"€","emoji":"😀"}, ensure_ascii=True, sort_keys=True)` → `'{"a": "\u2603", "e": "\u20ac", "emoji": "\ud83d\ude00", "\u2603key": 1}'` — every returned code point `< 0x80`, **keys escaped too**; the same input with `ensure_ascii=False` → `'{"a": "☃", "e": "€", "emoji": "😀", "☃key": 1}'`; omitting the kwarg equals the `True` form.

**Two things the flag is *not*:**
- **Not the transport charset.** `mimetype` is hardcoded `"application/json"` (`provider.py:105`, `:163`, `:213-214`) with no `ensure_ascii` branch. The `str`→UTF-8 bytes step for a real response happens in **werkzeug, outside this worktree** (`import werkzeug` failed in the interpreter used; only indirect in-tree evidence is `tests/test_testing.py:110-114`, which decodes the builder's bytes as `"utf8"` and gets `"€"`).
- **Not a JSON-escaping switch.** Mandatory escapes still apply under `False`: `ESCAPE` (`encoder.py:18`) + `ESCAPE_DCT` (`:21-32`); observed `json.dumps('a\nb"c', ensure_ascii=False)` → `'"a\\nb\\"c"'`, with U+2028 emitted literally.

**Value preservation (so the change is representational only).** `json.loads` of the ASCII form and the literal form both equal the original dict, and `"\ud83d\ude00"` decodes to `😀` — mechanism `decoder.py:91` (literal passthrough) and `:117-125` (`_decode_uXXXX` + surrogate recombination).

**In-tree tests that pin it:** `tests/test_json.py:47-54` parametrizes `(True, '"\\u2603"')` / `(False, '"\u2603"')` for `app.json.dumps("\N{SNOWMAN}")` — i.e. six ASCII characters vs the literal snowman; `tests/test_testing.py:110-114` sets `app.json.ensure_ascii = False`, builds `json="\u20ac"`, and asserts the bytes decode to `'"€"'`.

**Contradictions / ambiguity:** none between the sources reviewed — the docstring, the setdefault source, the CPython encoder branches, and both tests are mutually consistent.
