### 2. The modular registration unit is `Blueprint`, and its static route is installed at a different time from the app's

- Registration machinery: `Blueprint.add_url_rule` (`sansio/blueprints.py:412-443`) only calls `self.record(lambda s: s.add_url_rule(...))`; `Blueprint.register(app, options)` (`:273`) → `make_setup_state` (`:321`) → `BlueprintSetupState.add_url_rule` (`:87`), which joins the prefix `"/".join((self.url_prefix.rstrip("/"), rule.lstrip("/")))` (`:100`), forms the dotted endpoint `f"{self.name_prefix}.{self.name}.{endpoint}".lstrip(".")` (`:112`), and then calls `self.app.add_url_rule(...)` (`:110`). App side, both `@setupmethod`: `sansio/app.py:569-570 register_blueprint`, `:604-605 add_url_rule`.
- **App static route — eager, at construction**, inside `Flask.__init__` (`app.py:262-279`): gated on `if self.has_static_folder:` (`:267`), asserted `bool(static_host) == host_matching` (`:268-270`), registered with a **weakref closure** to avoid an app↔view reference cycle (#3761, `:271-273`), as `f"{self.static_url_path}/<path:filename>"`, `endpoint="static"`, `view_func=lambda **kw: self_ref().send_static_file(**kw)` (`:274-279`). An in-code comment explains it registers without checking the folder exists (it may appear while the server runs).
- **Blueprint static route — deferred, during registration** (`sansio/blueprints.py:323-328`): `if self.has_static_folder:` → `state.add_url_rule(f"{self.static_url_path}/<path:filename>", view_func=self.send_static_file, endpoint="static")`. Because it passes through the setup state, the rule is prefix-joined and the endpoint dotted.
- Runtime confirmation against this tree's own `src`: a fresh `Flask(__name__, static_folder="static")` already has exactly `('/static/<path:filename>', 'static')` with a `<lambda>` closure holding a `ReferenceType`; a blueprint with `url_prefix='/admin'` produces `('/admin/static/<path:filename>', 'admin.static')` and `url_for('admin.static', filename='test.txt') == '/admin/static/test.txt'`, both flat and nested files 200. Negative cases: a prefix-less blueprint adds a *second* `/static/<path:filename>` at endpoint `noprefix.static` and the app rule wins (blueprint-only file 404s); `static_folder=None` registers no `static` endpoint and raises `RuntimeError("'static_folder' must be set to serve static_files.")`.

### 3. Caching continuity comes from one config key plus one funnel, with one documented asymmetry

- **Same key on both sides**: `"SEND_FILE_MAX_AGE_DEFAULT": None` in `default_config` (`app.py:201`), read by identical bodies at `app.py:298` and `blueprints.py:72`; `timedelta` values convert to int seconds on both sides. This is what keeps the two components' cache behaviour consistent.
- **Single funnel**: `helpers.py:387-389 _prepare_send_file_kwargs` — `if kwargs.get("max_age") is None: kwargs["max_age"] = current_app.get_send_file_max_age`. Only the **app's** bound hook is wired in as the default; `helpers.py:498` documents it as `Flask.get_send_file_max_age`.
- **The one asymmetry, with its reason in code**: `blueprints.py:97-98` — "send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too" — hence `Blueprint.send_static_file` calls `self.get_send_file_max_age(filename)` (`:99`) and passes `max_age=` explicitly. Without that line the blueprint path would silently fall back to the app hook; with it, a `Blueprint` subclass can override its own caching and the two components stay coherent.
- **Semantics of `max_age=None`**: `CHANGES.rst:587-590` — `send_file` defaults `conditional=True`/`max_age=None`; `Cache-Control` is `no-cache` when `max_age` is unset, else `public` (`:pr:`3828`).
- Runtime probe: config `None` → app and blueprint both `Cache-Control: no-cache`, `max_age is None`; `3600`/`7200`/`timedelta(seconds=3600)` → both `public, max-age=<n>`; a `Blueprint` subclass hook returning `100` beats config `3600` on the blueprint path while the app path still reads `3600`; a `Flask` subclass hook returning `999` is picked up through `current_app` (and by plain `flask.send_file`/`send_from_directory`); explicit `max_age=42` bypasses the hook entirely.
