## Answer

**Short form:** in this tree (Flask `3.2.0.dev`, `pyproject.toml:3`; HEAD `85c5d93c`) there is no plugin/entry-point registry for routes — the "modular component" is the `Blueprint`, and the separation is a **sansio-vs-WSGI layering split with two registration timings that converge on one registration primitive and one cache-resolution rule.**

**1. Shared configuration base (sansio, no I/O, no HTTP).** `class Flask(App)` (`src/flask/app.py:81`) and `class Blueprint(Scaffold)` (`src/flask/sansio/blueprints.py:122`) both inherit `Scaffold`, so both answer "is static serving on?" with the same gate: `has_static_folder` = `self.static_folder is not None` (`src/flask/sansio/scaffold.py:241-246`) — i.e. **configured, not present-on-disk** — with `static_url_path` derived from the folder basename when unset (`scaffold.py:249-263`).

**2. Main application framework registers EAGERLY, inside `Flask.__init__`** (`def` at `app.py:226`): `if self.has_static_folder:` at `app.py:267`, rule added at `app.py:274-279` as `f"{self.static_url_path}/<path:filename>"`, `endpoint="static"`, view via a `weakref` (`self_ref`, `app.py:273`, comment cites issue #3761). The source gives the reason for not testing existence at `app.py:264-266`: the folder "might be created while the server is running", and Google App Engine stores static files elsewhere.

**3. Modular component registers DEFERRED, only at registration time.** Constructing a `Blueprint` registers nothing; `Blueprint.register` (`src/flask/sansio/blueprints.py:273`, docstring "Called by :meth:`Flask.register_blueprint`") does `if self.has_static_folder:` at `:323` and attaches `state.add_url_rule(f"{self.static_url_path}/<path:filename>", view_func=self.send_static_file, endpoint="static")` at `:325-328`. Chain: `App.register_blueprint` (`sansio/app.py:~570`) → `blueprint.register(self, options)` (`sansio/app.py:595`) → `BlueprintSetupState.add_url_rule` (`sansio/blueprints.py:87-105`), which joins `url_prefix`, sets subdomain, and namespaces the endpoint to `f"{name_prefix}.{name}.{endpoint}"` before calling **the same `App.add_url_rule`** (`sansio/app.py:~605`) the app's own route uses. The static block is guarded **only** by `has_static_folder` — not by `_got_registered_once` (that flag is set at `:317` and only guards `_check_setup_finished`, `sansio/blueprints.py:~211-219`). Nested blueprints go through `Blueprint.register_blueprint` (`:256`), recursed at the end of `register`.

**4. Caching consistency is achieved in the WSGI layer, not in sansio.** `grep -n max_age src/flask` matches only `src/flask/app.py`, `src/flask/blueprints.py`, `helpers.py`, `sessions.py` — **zero `max_age` references anywhere under `sansio/`**. Both concrete classes carry byte-identical duplicated bodies, each self-labelled "a duplicate": `get_send_file_max_age` (`app.py:281` / `blueprints.py:55`) reads `current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]` and converts `timedelta` → int seconds; `send_static_file` (`app.py:308` / `blueprints.py:82`) **pre-resolves** `max_age = self.get_send_file_max_age(filename)` and passes it into `send_from_directory` (`app.py:325-327` / `blueprints.py:99-101`), with the source comment stating why: *"send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too"*. The generic fallback lives at `helpers.py:387-389` (`if kwargs.get("max_age") is None: kwargs["max_age"] = current_app.get_send_file_max_age`). So the same config key and the same hook semantics apply on both paths, and a subclass override is honored on either — that is the concrete content of "consistent caching behavior".

**5. It is observed, not just inferred.** `tests/test_helpers.py:47-104` (`test_static_file`) checks `None` default, `SEND_FILE_MAX_AGE_DEFAULT=3600`, and a subclass hook returning `10`, over both `app.send_static_file` and plain `flask.send_file`; `tests/test_blueprints.py:223` (`test_default_static_max_age`) registers a `Blueprint` whose `get_send_file_max_age` returns `100` against config `3600` and asserts `cc.max_age == 100` (assertion ~`:242`); `tests/test_basic.py:1412` exercises the app route over HTTP plus `url_for("static")`. The blueprint-side endpoint namespacing shows up at `tests/test_blueprints.py:~210` (`url_for("admin.static") == "/admin/static/test.txt"`). The executor's probes additionally showed the deferred route working with `url_prefix`, the blueprint hook winning over app config over a real HTTP route, and an app route registered while the static dir is absent returning 404 then 200.

**6. "Registration architecture" = blueprints only.** An absence search found no route/component plugin registry; the only entry-point group in the codebase is `importlib.metadata.entry_points(group="flask.commands")` at `cli.py:604`.
