## Modular component registration architecture for static asset serving

Reading "modular component" as the blueprint (the framework's only reusable registration unit, and the side of every app/blueprint comparison in the evidence), the architecture is a **three-layer split**: one shared configuration surface in the sansio layer, plus two independent, self-contained registration-and-implementation pairs — one in the app framework, one in the reusable component — that never call into each other and are kept caching-identical by deliberate duplication over a single shared config key.

**Layer 1 — the shared configuration surface (`Scaffold`).** `src/flask/sansio/scaffold.py:56-70` defines `class Scaffold`, documented as *"Common behavior shared between :class:`~flask.Flask` and :class:`~flask.blueprints.Blueprint`"*. It owns the static inputs exactly once: `static_folder` (`scaffold.py:223-238`, joining `root_path`), `has_static_folder` (`240-246`), and `static_url_path` (`248-265`, deriving `f"/{basename}"` from the folder when unset). `src/flask/sansio/README.md` states this layer *"cannot do any IO, nor be part of a likely IO path … cannot use the Flask globals"* — that constraint is precisely what forces the request-time methods down into the two concrete modules rather than being shared here.

**Layer 2 — the framework registers and implements its own static route.** In `Flask`'s constructor, `src/flask/app.py:263-279`: when `self.has_static_folder`, it calls `self.add_url_rule(f"{self.static_url_path}/<path:filename>", endpoint="static", host=static_host, view_func=lambda **kw: self_ref().send_static_file(**kw))`, with `self_ref = weakref.ref(self)` and the comment *"Use a weakref to avoid creating a reference cycle between the app and the view function (see #3761)."* The implementations are `Flask.get_send_file_max_age` (`app.py:281-307`) and `Flask.send_static_file` (`app.py:308-328`) — the app serves its own assets, with no dispatcher and no delegation to a component registry.

**Layer 3 — the component registers itself separately, in the sansio layer, and implements the same two methods one module up.** Inside `Blueprint.register` (`src/flask/sansio/blueprints.py:320-327`), after the name-collision check at `305-317`, `if self.has_static_folder: state.add_url_rule(f"{self.static_url_path}/<path:filename>", view_func=self.send_static_file, endpoint="static")`. `docs/blueprints.rst:206-213` records the resulting bundle name as `<blueprint_name>.static`. The implementations live in the **non-sansio** module — `src/flask/blueprints.py:55-81` and `:82-101`, in `class Blueprint(SansioBlueprint)` — because they need `current_app` and `send_from_directory`. Registration is in `sansio`, implementation in the IO layer: that is the seam that keeps the sansio layer IO-free while still letting the component own its route.

**How caching stays consistent without shared code.** The app and the component read *the same* config key and convert it the same way, by design:

- One key, one default: `"SEND_FILE_MAX_AGE_DEFAULT": None` in `Flask.default_config`, `src/flask/app.py:201`. `None` means conditional requests, not a timed cache (docstring at `app.py:286-288`).
- Two identical bodies: `app.py:298-306` and `blueprints.py:72-80` both do `value = current_app.config["SEND_FILE_MAX_AGE_DEFAULT"]`; `None → None`; `timedelta → int(value.total_seconds())`; else the value itself. The retriever verified them byte-for-byte; my own reads of `app.py:281-307` and `blueprints.py:55-101` show the same text in both places.
- Two identical view bodies: `app.py:320-328` and `blueprints.py:94-101` carry the same comment — *"send_file only knows to call get_send_file_max_age on the app, call it here so it works for blueprints too."* — then `max_age = self.get_send_file_max_age(filename)` and `send_from_directory(t.cast(str, self.static_folder), filename, max_age=max_age)`. The blueprint resolves `max_age` **itself** precisely because the generic `send_file` path can only see the app; that resolution is what makes component caching work at all.
- The generic path closes the loop: `src/flask/helpers.py:387-389` sets `kwargs["max_age"] = current_app.get_send_file_max_age` when `max_age` is `None`, documented at `helpers.py:492-494`, so plain `send_file`/`send_from_directory` also run through the app's method.
