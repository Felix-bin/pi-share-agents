# How `MethodView.__init_subclass__` resolves conflicting `methods`

The method-dispatching view class is `MethodView` (`src/flask/views.py:137`, docstring at `:139`: "Dispatches request methods to the corresponding instance methods."). Its `__init_subclass__` hook is at `src/flask/views.py:165-180`, and it resolves conflicting `methods` attributes **by set-union over the direct bases — there is no MRO precedence and no "first base wins"**. The four behaviours, in the order the code runs:

1. **An explicit `methods` on the subclass short-circuits the hook entirely.** `if "methods" not in cls.__dict__:` (`src/flask/views.py:168`) guards the whole block. Because `__dict__` is tested rather than `getattr`, only a `methods` set on the subclass itself triggers this — an *inherited* `methods` does not. When it does trigger, the hook leaves the value untouched: no merging, no upper-casing, and a declared list stays a list.
2. **Otherwise, conflicting parent `methods` are unioned across direct bases.** `for base in cls.__bases__:` (`:170-173`) checks `getattr(base, "methods", None)` and, for each truthy one, does `methods.update(base.methods)` into a fresh `set()`. So parents with disjoint or overlapping method sets are simply additive; identical names collapse in the set, distinct ones all survive, and the ordering of `__bases__` is irrelevant to the result. A base that declares nothing contributes nothing, because `View.methods` defaults to `None` (`src/flask/views.py:51`).
3. **Handlers defined on the class are then added by name.** `for key in http_method_funcs:` (`:175-177`) adds `key.upper()` for every member of `http_method_funcs` — `frozenset(["get", "post", "head", "options", "delete", "put", "trace", "patch"])` at `src/flask/views.py:11-13` — where `hasattr(cls, key)` holds, so inherited handler functions count too.
4. **The result is only assigned when non-empty.** `if methods: cls.methods = methods` (`:179-180`). An empty result leaves `cls.methods` unset, so it falls back to the inherited/`View.methods` value (`None`, i.e. the route default GET/HEAD/OPTIONS) rather than becoming an empty set.

**Boundary the hook does not cover.** It runs once, at class-creation time, so `cls.__bases__` is fixed when it executes: assigning `methods` on a parent later, or re-parenting/monkey-patching, is not re-merged. And because only *direct* bases are traversed, a `methods` set declared on a grandparent reaches a grandchild through the intermediate class's inherited attribute via `getattr`, not by full-MRO traversal.

**The behaviour is pinned by three tests in `tests/test_views.py`:**

- `test_methods_var_inheritance` (`:189-204`): `BaseView` sets `methods = ["GET", "PROPFIND"]` (`:191`), `ChildView(BaseView)` defines `get`/`propfind`, and the assertion `ChildView.methods == {"PROPFIND", "GET"}` (`:204`) shows the parent's collection merged with the name-derived handlers, normalised into a set.
- `test_multiple_inheritance` (`:207-223`): `GetDeleteView(GetView, DeleteView)` with an empty body — GET and DELETE are both served and `sorted(GetDeleteView.methods) == ["DELETE", "GET"]` (`:223`), i.e. both parents' methods survive. This is the direct refutation of precedence semantics.
- `test_remove_method_from_parent` (`:226-242`): `class View(GetView, OtherView): methods = ["GET"]` (`:235-236`); GET works, POST returns 405, and `sorted(View.methods) == ["GET"]` (`:242`) — the explicit own-dict `methods` suppressed the parents' `post` entirely, confirming behaviour 1.

**Contradiction between sources (line bounds only, substance identical).** The planner quoted the hook as `src/flask/views.py:165-179` and `http_method_funcs` as `:12-14`, and the test spans as `207-222` / `225-240`; the retriever gave `165-180`, `11-13`, `207-222`, `225-240`. Grep against the working tree resolves these to the hook at `165-180` (the final `cls.methods = methods` sits at `:180`, one line past the planner's range), `http_method_funcs` at `11-13`, and the tests at `189-204`, `207-223`, `226-242`. No disagreement about behaviour, only off-by-one range drift.
