# How the `--cert` conversion method implements its fallback chain

`CertParamType.convert` (`src/flask/cli.py:791-825`) resolves the `--cert` value by trying four things in a fixed order, each attempt guarded so that failure falls through to the next. It is the only `CertParamType` in the worktree, and it is bound to the `run` command's option at `src/flask/cli.py:886-891` as `--cert`, `type=CertParamType()`, `is_eager=True`.

**Gate before the chain — SSL availability.** The method first does `try: import ssl` / `except ImportError: raise click.BadParameter('Using "--cert" requires Python to be compiled with SSL support.', ctx, param) from None`. If Python itself lacks `ssl`, the option aborts immediately and no fallback is attempted.

**Attempt 1 — an existing file path.** `try: return self.path_type(value, param, ctx)`. `self.path_type` is built in `__init__` (`:788-789`) as `click.Path(exists=True, dir_okay=False, resolve_path=True)`, so a literal existing file returns its resolved absolute path. Because this is tried first, a file actually named `adhoc` in the working directory is treated as a path, not as the adhoc marker — the string branch is only reachable after this attempt raises `click.BadParameter`.

**Attempt 2 — the `adhoc` marker.** On `except click.BadParameter` the value is normalised with `value = click.STRING(value, param, ctx).lower()` (`:806`); the `.lower()` makes the marker case-insensitive. If `value == "adhoc"`, a nested gate runs `import cryptography` and, on `ImportError`, raises `click.BadParameter("Using ad-hoc certificates requires the cryptography library.", ctx, param)`; if `cryptography` is importable the method `return value`, i.e. the literal lowercase string `"adhoc"`.

**Attempt 3 — an importable `ssl.SSLContext`.** `obj = import_string(value, silent=True)` (`:820`, `from werkzeug.utils import import_string` at `src/flask/cli.py:21`), then `if isinstance(obj, ssl.SSLContext): return obj`. A dotted import path that resolves to an `SSLContext` instance is returned as-is.

**Final fall-through — a bare `raise` (`:825`).** This is the subtle part: `import_string(..., silent=True)` returns `None` rather than raising when the import fails, so the bare `raise` re-raises the *still-active* `click.BadParameter` from the failed path attempt at `:803-804`. The consequence, directly implied by those two facts, is that a non-importable name such as `not_here` and an importable-but-wrong-type name such as `flask` both surface the **path** validation error message, not an import-specific one.

**Where the `(cert, key)` pairing happens — not in `convert`.** It is in `_validate_key` (`src/flask/cli.py:828-864`), the callback of the companion `--key` option (`:892-899`). It reads `cert = ctx.params.get("cert")`, computes `is_adhoc = cert == "adhoc"` and `is_context = isinstance(cert, ssl.SSLContext)` under its own guarded `import ssl`, and when `--key` is given assigns `ctx.params["cert"] = cert, value` — producing the `(cert, key)` tuple. Its rejections are: `adhoc` plus `--key`, `SSLContext` plus `--key`, `--key` with no `--cert`, and a cert file given without `--key`. So `convert` chooses *which kind* of cert was supplied; `_validate_key` then enforces the kind-appropriate key pairing.
