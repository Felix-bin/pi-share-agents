## How `_AppCtxGlobals` balances raising vs. defaulting

The balance is **by method, not by a single flag**: `_AppCtxGlobals` in `src/flask/ctx.py` (class at lines 29–115) keeps Python's normal object semantics strict for the attribute protocol and offers dict-style defaults only through an explicit API.

**Strict branch — attribute access and deletion raise `AttributeError`.** `__getattr__` (lines 52–56) does `try: return self.__dict__[name]` / `except KeyError: raise AttributeError(name) from None`. `__delattr__` (lines 61–65) is exactly symmetric: `del self.__dict__[name]` under a `KeyError` becomes `AttributeError(name) from None`. The `from None` suppresses the chained `KeyError`, so a caller sees plain object semantics and never a dict error. This is safe to make strict because assignment cannot fail: `__setattr__` (lines 58–59) is a raw `self.__dict__[name] = value` that accepts arbitrary names. The only rationale the source states is the comment at lines 49–50 — "Define attr methods to let mypy know this is a namespace object that has arbitrary attributes" — which is a typing rationale, not a documented error-handling policy.

**Permissive branch — the dict-like methods return defaults.** `get(name, default=None)` (lines 67–76) returns `self.__dict__.get(name, default)` and never raises. `setdefault(name, default=None)` (lines 92–101) returns `self.__dict__.setdefault(name, default)`, never raises, and writes when the name is absent (first write wins). `pop` (lines 78–90) takes `default=_sentinel` and branches: `if default is _sentinel: return self.__dict__.pop(name)` else `self.__dict__.pop(name, default)`. The module-level `_sentinel = object()` (line 26) is what makes `pop("x")` distinguishable from `pop("x", None)`, so supplying a default suppresses the exception while omitting one does not.

**The asymmetry that matters for the "removal" case.** Bare `pop(name)` without a default is the one removal path that still raises the raw `KeyError`, not `AttributeError` — and the docstring says so explicitly at lines 82–83 ("instead of raising a ``KeyError``"). So errors and defaults coexist per call site: attribute access/deletion always raise `AttributeError`; `get`/`setdefault`/`pop`-with-default always return a value; `pop`-without-default raises `KeyError`. The class docstring (lines 30–47) documents only `'key' in g` and `iter(g)` and mentions neither exception type.

**Repo cross-checks.** `tests/test_appctx.py:134–153` (`test_app_ctx_globals_methods`) pins this exact split: `flask.g.get("foo") is None` (136) and `flask.g.get("foo", "bar") == "bar"` (137), `setdefault("bar", ...)` keeping the first value (142–145), `flask.g.pop("bar") == "the cake is a lie"` then `with pytest.raises(KeyError): flask.g.pop("bar")` (146–148), and `flask.g.pop("bar", "more cake") == "more cake"` (150). The documentation recommends the non-raising form for teardown: `docs/appcontext.rst:115–123` pairs `if 'db' not in g: g.db = connect_to_database()` with `g.pop('db', None)`, and `docs/api.rst:168,179` exposes the class as the default of `Flask.app_ctx_globals_class` via `:class:` / `:members:` autodoc.
